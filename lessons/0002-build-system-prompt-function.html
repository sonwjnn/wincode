buildSystemPrompt là gì?

Một function biến nhiều nguồn instruction rời rạc thành đúng “gói hướng dẫn” mà model nhận được ở một thời điểm cụ thể.

CompositionBuilder-likePi · OMP · OpenCode
Định nghĩa Lợi ích Pattern Tự kiểm tra Bài 0001 Reference

1. Định nghĩa ngắn

buildSystemPrompt là composition root cho system prompt. Nó nhận các input như base instructions, tools, rules, skills, project context hoặc environment; sau đó quyết định block nào được đưa vào và thứ tự ghép chúng.

Nó không nhất thiết “viết prompt bằng AI”. Thường nó là code deterministic: cùng input và cùng configuration sẽ tạo ra cùng cấu trúc prompt.

Mô hình:

systemPrompt = assemble(base, context, policy, environment)

Trong đó assemble có thể trả về một string, một array các blocks, hoặc một request object tùy runtime.

2. Lợi ích

  1. Centralize policy: role, workflow và safety rules không bị rải trong nhiều call site.
  2. Control ordering: context nào đến trước/sau được nhìn thấy và review rõ ràng.
  3. Gate dynamic data: chỉ thêm skills, tool text hoặc rules khi capability/configuration cho phép.
  4. Testable boundary: có thể test output của builder mà không cần chạy cả agent loop.
  5. Provider seam: giữ prompt assembly tách khỏi code thực thi tool hoặc gọi model.

Lợi ích quan trọng nhất: biến prompt từ một blob khó kiểm soát thành một output có cấu trúc, có thứ tự và có nguồn gốc.

3. Thuộc design pattern nào?

Câu trả lời chính xác: không phải một GoF pattern chính thức. Tên function mô tả trách nhiệm, không tự chứng minh pattern. Tuy vậy, cách dùng thường gần với ba ý tưởng sau:

Khái niệm Vì sao gần Không nên gọi quá mức
Builder Tạo output phức tạp từ nhiều phần, với các phần optional và thứ tự rõ. Nếu chỉ nối vài string đơn giản, gọi “Builder pattern” có thể thổi phồng thiết kế.
Composition / pipeline Mỗi layer đóng góp một block; function là nơi compose các layer thành output cuối. Đây là mô tả kiến trúc tổng quát, không phải class pattern cụ thể.
Factory Ở OpenCode, provider/model có thể quyết định static prompt asset nào được chọn. Factory chỉ mô tả bước chọn/tạo variant; không mô tả toàn bộ assembly.

Cách gọi nên dùng: “prompt assembly builder” hoặc “prompt composition function”. Chỉ gọi là Builder pattern khi function thật sự xây một output nhiều phần với optional steps và invariants cần giữ.
