Mô hình tối thiểu

System prompt không nhất thiết là một file. Nó là kết quả của một assembly pipeline: base policy + runtime context + tool contract + project instructions, được ghép theo thứ tự cố định trước khi gửi model.

Đừng trộn ba lớp:

  • Instruction text: model nên hành xử thế nào.
  • Tool contract: tool nào tồn tại, schema nào hợp lệ, thường truyền ngoài prose.
  • Data/context: cwd, rules, transcript, skill body, git state — thay đổi theo request hoặc workspace.

Pipeline một dòng

Pi — single-string assembly

  1. Default hoặc custom base
  2. Tool snippets và guidelines
  3. Append prompt
  4. Project context
  5. Skills
  6. Cwd

OMP — template blocks

  1. Render default/custom instruction template
  2. Optional computer-safety block
  3. Project/environment footer
  4. Active-repository block

OpenCode — provider selection + request preparation

  1. Chọn base theo provider/model hoặc agent prompt
  2. Environment
  3. Discovered instructions
  4. MCP instructions và skills
  5. Structured-output directive
  6. Transform và gửi theo provider adapter

Wincode — current composition root

  1. Base agent instructions
  2. Resolved agent instructions
  3. Tools truyền riêng
  4. Activated skill context là user message

Heuristics khi thiết kế

  1. Giữ tool schema ngoài prose; chỉ thêm tool policy cấp cao nếu cần.
  2. Đặt context vào named block có provenance và thứ tự deterministic.
  3. Giữ volatile environment data ngoài cacheable prefix khi có thể.
  4. Lazy-load skill body; đừng nhồi toàn bộ catalog vào system prefix.
  5. Tách compaction prompt khỏi coding-agent prompt.
