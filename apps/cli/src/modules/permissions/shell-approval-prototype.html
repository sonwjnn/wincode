Mô hình duyệt lệnh shell — Wincode hôm nay vs đề xuất vs opencode/pi

Câu hỏi prototype: tại sao pwd, cd hay cwd lại bắt người dùng approval, và model duyệt lệnh nên được sửa thế nào? Demo này chạy cùng một lệnh qua 3 model song song — bấm lệnh, xem chuỗi quyết định từng model, rồi tự do bấm "Cho phép 1 lần / Luôn cho phép / Từ chối / Auto" để cảm nhận điểm khác biệt. Mọi thứ nằm trong bộ nhớ, không lưu gì cả.

Tóm tắt 3 model: ① Wincode hôm nay — mọi lệnh shell đều ask (mặc định), lệnh phá hoại bị trần an toàn (không auto / không remember), "Luôn cho phép" ghi grant shell * (mở khóa mọi lệnh). ② Đề xuất cho Wincode — giữ nguyên trần an toàn, thêm allowlist đọc-chỉ mặc định (như pi), grant theo đúng lệnh (như opencode), cd miễn duyệt trừ khi ra ngoài workspace. ③ opencode / pi — opencode mặc định "*": "allow" (rất thoáng), pi qua extension dùng "*": "ask" + allowlist + deny rm/sudo; "Luôn cho phép" của opencode ghi tiền tố an toàn như git status *.

Kịch bản có hướng dẫn — bấm từng bước, quan sát 3 lane

PROTOTYPE — đánh giá, không phải code production. Logic thuần trong <script id="pure-module"> mô phỏng trung thực shell-safety.ts, policy.ts (glob, last-match-wins, fallback), approval-resolution.ts và tool-gate.ts (grant shell *, trần an toàn) của Wincode; phần opencode/pi theo source của họ (permission.ts, shell.ts, arity.ts; pi-permission-system). Khi chốt hướng, phần được chọn lift vào modules/permissions/ và file này bỏ đi (hoặc commit sang branch throwaway).
