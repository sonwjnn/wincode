# Register bundled and file-loaded Plugins through one PluginAPI

Status: accepted

ADR-0041 moves MCP and Subagents implementations into separately loaded packages, removes Coding-Agent's static dependencies on both, and exports the Plugin contract from the Coding-Agent package root rather than a Plugin subpath. The distribution selects both by default for application entry points; SDK callers still opt in. The bundled-only naming and MCP-specific permission branch are replaced by public, general Plugin contracts without a Tool Gate bypass. The host exposes a general config snapshot and Plugin status/panel boundary instead of reading MCP internals.

Coding and shell tools remain native Session capabilities. MCP and Subagents are independently loadable packages that implement the same public Plugin API as explicitly enabled Plugin files. Application entry points select the distribution packages by default; SDK callers select Plugin files with explicit paths. File-loaded Plugins remain limited to explicitly enabled paths under ADR-0036. Every Plugin declares a stable Plugin Identifier and registers through `definePlugin({ id })`. Skills remain a native host feature. Plugin authors import the contract and general Session SDK from the `@wincode/coding-agent` package root.

## Registration and lifecycle

`registerTool` registers one tool per call. A Plugin may call it during factory loading, a Session hook, or a pre-Agent-Turn hook. The latter receives public Turn context, including Session ID, Agent ID, workspace, and abort signal; it does not expose internal MCP snapshots or delegation ports. A Plugin may replace its own tool by name or call `unregisterTool`; another Plugin cannot take that name. Turn registrations override Session registrations, which override factory registrations for the same Plugin. Unregistering in a narrower scope masks an outer registration only within that scope. In-flight Tool Calls keep the handler they resolved with; changes affect later Turns. The selected tool definitions can therefore differ between Turns without mutating an active Turn.

`registerCommand` is available during factory loading and Session hooks, not pre-Turn hooks. A Plugin may replace its own command. A collision with another Plugin or a host command fails the attempted registration. Factory registration remains transactional: a failed factory publishes none of its contributions. A failed later registration leaves earlier valid registrations in place and emits a diagnostic. If a pre-Turn hook fails, that Plugin contributes nothing to that Turn; other Plugins continue. Factory, Session, and process shutdown hooks retain their existing lifecycle meaning.

Plugin tools accept Zod or JSON Schema input definitions and return a single public result shape representing success or error. The application composition root resolves selected Plugin tools for each Agent Turn and wraps their execution with the Tool Gate. Registration alone grants neither Agent visibility nor permission. The host resolves Plugin permission by action and resource through the common Tool Gate; direct model-visible names and Plugin metadata cannot bypass the default `ask`. This preserves the permission boundary in ADR-0030 while removing the separate bundled-vs-file-loaded Plugin registration contracts.

The Plugin Identifier owns its tools, commands, diagnostics, and lifecycle across scopes. ADR-0037's file path independence, file-loaded tool namespace and permission action, duplicate file ID precedence, and deterministic loading order remain. Identity applies to bundled and file-loaded Plugins, not native coding/shell capabilities. A command collision or late registration error no longer invalidates an otherwise valid Plugin; the failing call follows the phase rules above. Plugin Commands remain Interactive-only under ADR-0036.

This replaces the separate built-in registry and minimal file-loaded authoring interface in ADR-0038. It does not authorize automatic project Plugin discovery, a sandbox, Plugin-controlled permission bypass, or a public raw Session object.
