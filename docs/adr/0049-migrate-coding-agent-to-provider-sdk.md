# Migrate Coding-Agent to the Provider SDK with a credential cutover

Status: accepted target; implementation pending

ADR-0048's independent `@wincode/ai` SDK shipped in PR #198. Coding-Agent still uses Connections, a curated Model Catalog, a secret-bearing Model Target, and a separate Model Client. Migrate all execution modes and the Agent Runtime together to the SDK Provider/Provider Model identity, rather than keep two request paths or a permanent compatibility adapter. The Session Record remains historical evidence, not a live Provider Model lookup result.

## Boundaries and ownership

- One Session Host owns one ProviderCollection and fresh Provider instances across its Agent Turns; closing the Host closes provider-owned resources, including Google CachedContent. A process-level composition of the six separately imported built-ins and explicitly enabled, trusted Plugin provider factories supplies each Host. Provider instances are never reused across Hosts. Credential and model stores are application-owned, shared at user scope, and not tied to a Host's lifetime. A model refresh changes the next turn's model view, never an in-flight invocation.
- Coding-Agent registers OpenAI, Anthropic, Google, OpenCode Go, DeepSeek, and OpenRouter, plus custom Providers declared by trusted TypeScript Plugins. Config selects Plugin paths; config data alone cannot define an arbitrary protocol. A Plugin can define its own connection interaction, but Coding-Agent owns the CredentialStore and presents/stores the result. Headless one-shot and RPC requests never start interactive login implicitly; they return an actionable structured error instead. Browser OAuth remains available through an explicit interaction.
- Reject duplicate Provider IDs, including collisions with built-ins. Persist a custom Provider's owner as its Plugin ID **and trusted source identity**, not just its Provider ID or a shared workspace name. A different owner cannot receive the former owner's credential or model snapshot; require explicit approval and a fresh connection. When the owner Plugin is absent, retain but quarantine its credentials and model snapshot. A child Session sees only its explicitly selected Plugin paths. Reload replaces the Provider composition only when Session Hosts are idle; if candidate loading fails and Project trust has not changed, keep the previous composition. Never restore a Provider sourced from newly untrusted project code.
- Extend the provider-neutral SDK chat contract before cutting over the Agent Runtime: preserve requested output limits, provider-neutral reasoning effort, cache preferences and cache-key/warming behavior, tool failures, opaque continuation, usage, abort, and structured provider/auth/transport errors. Coding-Agent maps ThinkingLevel to declared supported effort values; absent support means provider default, not guessed support. The Agent Runtime still owns Tool Call execution, Session Context, and Agent Turn events; it does not handle provider credentials or wire protocols. Do not narrow the current TUI, JSON, RPC, compaction, or subagent behavior as a side effect of replacing ModelClient/ModelStepRequest.

## Credential cutover

Users explicitly reconnect; do **not** copy or reuse a `connections-v2` credential. The new application CredentialStore uses a distinct namespace on the existing OS secret-store/secure-file-fallback mechanism, keyed by Provider ID and, for Plugin Providers, owner identity. The app must add deletion and verification capabilities for the legacy OS secret backend and file fallback, including cases where both hold material. The migration gate runs before any execution mode can send a model request. Remove known legacy provider credentials from every backend, verify absence, then record completion durably. Never mark completion before verification or silently treat an inaccessible backend as empty.

Deletion is destructive and not transactional across OS and file backends. If it fails after partial progress, **fail closed**: do not run the SDK cutover, report which entries were removed and which could not be verified, and permit idempotent retry. Do not claim the deletion rolled back or recover by silently using the old connection path. Only after the gate succeeds may the user connect again into the new store. Do not delete Session history or attachments.

## Model selection and historical Sessions

- Register Provider Models rather than curating a product allowlist. Restore user-scoped model snapshots offline; refresh only after an explicit connect or refresh action. A failed or cancelled refresh retains last-known models. `getModels()` is last-known data, `getAvailable()` means configured auth, and neither proves the endpoint is reachable.
- A configured default, Agent pin, Session selection, or Plugin `setModel()` whose `{providerId, modelId}` is not currently known and invocable must not silently fall back. Show the stored identity and require an explicit new choice. Old Session Records retain their provider/model IDs and remain readable when a Provider disappears; an absent model cannot be invoked for a new turn, including compaction. Compaction requires explicit selection of a currently usable model instead of calling a vanished one or substituting a default.
- Capabilities, prices, context/output limits, thinking efforts, and cache tiers are model-published metadata, not values inferred from a neighboring model or the former static catalog. Missing context limits disable threshold-based automatic compaction; manual compaction can still use a selected available model. Unknown price is displayed as unknown, not zero cost. UI/config only offer supported cache tiers and efforts; unsupported cache retention remains a best-effort SDK preference rather than a runtime failure. Preserve Session usage and cache-warming accounting.

## Consequences and supersession

The one-way part is automatic deletion of legacy credentials: rollback of binaries cannot restore deleted secrets, and users must reconnect. The code cutover can be reverted, but not the credential deletion. This rejects a seemingly easier, permanent adapter and a silent fallback to a different model. Build and validate the SDK extensions and secure storage gate before changing any application send path; keep the runtime cutover atomic across modes and remove the old application-specific interfaces only after their consumers have migrated. Historical Session identity remains intact.

At implementation cutover, supersede ADR-0012's static allowlist rule and update the current Connection Provider/Model Catalog/Model Target definitions in `GLOSSARY.md`. Until then they describe the running application, while this ADR describes the accepted target. ADR-0048 remains the SDK foundation; this ADR records the application-specific migration choices.
