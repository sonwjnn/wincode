# Distribute MCP and Subagents through the public Plugin boundary

Status: accepted

The MCP and Subagents package implementations are split across Coding-Agent built-in adapters and their own domain packages. Move each entire Plugin factory and Plugin-owned behavior, with its unit tests, into `@wincode/mcp` and `@wincode/subagents`. Coding-Agent owns the general Plugin loader, Session SDK, config snapshot interface, Tool Gate, and Session lifecycle, not MCP servers or Subagents task orchestration. The packages must work through the public Plugin boundary rather than internal host imports or Plugin-specific host branches.

Publish `@wincode/coding-agent` and expose public Plugin and Session SDK contracts from its package root. Both Plugins import that root, not host-internal paths or subpaths; Coding-Agent does not import either package. The `@wincode/cli` distribution package owns the `wincode` executable and declares Coding-Agent, MCP, and Subagents as runtime dependencies, keeping the host package independent of its optional Plugins. The distribution enables both packages for application entry points by default without downloading code at startup. A missing default package without an explicit replacement is an installation error; disabling a Plugin explicitly does not require its package. SDK callers select Plugins explicitly. A user-selected source may replace either distributed Plugin; load only one source per Plugin Identifier and report which source won. Project files alone cannot authorize Plugin execution. The package graph stays acyclic because distribution selection does not require static application imports of these packages.

Subagents owns its task store, coordinator, recovery, and Plugin factory; retain durable task identities, explicit result acknowledgement, recovery, and report delivery. It explicitly selects Plugin source paths for each child Session, including its own source so the child can submit a result; children do not automatically inherit every parent Plugin. The Session SDK accepts selected paths generically and does not enumerate Subagents in its Plugin ID types. Subagents owns its task database path and configuration rather than requiring a generic host storage API.

MCP owns its registry, server lifecycle, configuration validation/resolution, and per-Turn tool registration. The host supplies a general, read-only merged config snapshot with provenance and refresh, preserving existing configuration precedence; MCP interprets its own section, rather than copying the ConfigStore merger or requiring `getMcpConfig()` in the host. Preserve MCP tool identities and permission rules without a host `id === "mcp"` branch or a Plugin-selectable trusted bypass. The common Tool Gate evaluates Plugin actions and resources, including actions whose names collide with native actions, without allowing an external Plugin to impersonate a native tool. MCP contributes status and actions (including reconnect and toggle) through a generic Plugin status/panel contract. The TUI renders those contributions and keeps the existing status and panel entry points without importing MCP registry types or MCP-specific components. Project-sourced local MCP commands are not started automatically; local processes must be configured by the user. Project-sourced remote headers are rejected, and a project URL cannot redirect user-configured headers; authenticated remote endpoints and headers belong in user configuration. MCP permission actions use the owner-qualified `plugin:mcp:<server>_<tool>` namespace, so action-family rules use patterns such as `plugin:mcp:external_*`; remembered Plugin approvals cannot grant host filesystem permissions.

The public Plugin registration contract permits any Plugin to request a direct model-visible tool name, subject to shared collision checks, so Subagents' `delegate`/`submit_result` and existing MCP tool names remain stable when file-loaded. Direct names grant no permission exception: tool visibility and Tool Gate decisions remain separate.

This revises ADR-0010's application-owned MCP transport placement, ADR-0037's unconditional file-loaded tool namespace rule, ADR-0039's bundled MCP/Subagents composition and MCP-only permission branch, and ADR-0040's packaging surface while preserving its Session and delegation contracts. ADR-0036's explicit enablement rule still applies to user/project-supplied Plugin files; a package installed and selected by the distribution is not project-driven discovery.
