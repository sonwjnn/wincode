# Expose a general Session SDK and let the Subagents Plugin own delegation

Status: accepted

Delegated Sessions currently depend on an application-internal task runtime registration, so a Plugin cannot create and manage Agent Sessions through the same public contract used by Wincode. Wincode will publish a general Session SDK from `@wincode/coding-agent`, modeled on Pi's `createAgentSession` and `SessionManager`. Callers can create or reopen a Session, prompt or continue it, subscribe to events, and dispose its live handle. The caller owns handle cleanup. Model, tools, workspace, storage, and resource loading are configurable; omitted settings resolve from Wincode configuration. The SDK's default tool set includes core coding and shell Plugins. MCP and Subagents are selected explicitly by SDK callers. File-loaded Plugins are included only when their paths have been explicitly enabled in user-controlled Wincode configuration or passed by the caller, never by project discovery.

The Subagents Plugin uses this SDK to create and manage child Sessions and to choose each child's Plugin set explicitly. It owns task orchestration and durable task/report records, using its own storage implementation as needed. The host provides general Session operations, including a durable message delivery operation that wakes an idle Session at a safe boundary; it does not expose a delegation-specific runtime port or a generic Plugin storage service. Plugin context supplies parent Session identity and public SDK operations, not the application's raw Session object. This revises implementation ownership in ADR-0035 while retaining its observable delegation contract.

A child resolves its Agent configuration and Tool Permission independently, as in Pi. There is no mandatory parent permission ceiling. Agent configuration and parent Plugins may provide optional capability ceilings outside model tool arguments; these restrictions intersect with the child's own choices and are snapshotted when the child is created. The Tool Gate still decides each actual call. Delegated tasks retain durable child Session and task identities, explicit `submit_result` acknowledgement, correlated reports, cancellation, and parent inbox ordering from ADR-0035. Normal shutdown cancels active children and reports that outcome. After an unclean shutdown, unconfirmed work is marked interrupted and durably reported without replaying model or tool work; an operator may explicitly reopen and continue its Session. Interactive and RPC Hosts continue an eligible idle parent with pending reports; Print and JSON leave them pending for explicit continuation.

This boundary lets a caller build other Session-based Plugins without adopting Subagents' task model or persistence format. It supersedes ADR-0038's absence of Agent control and its internal `registerSessionDelegationRuntime` arrangement.
