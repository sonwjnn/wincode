# Expose a general Session SDK and let the Subagents Plugin own delegation

Status: accepted

ADR-0041 locates the Subagents Plugin implementation in its own package, publishes the Plugin and Session SDK contracts at the Coding-Agent package root, and assigns default Plugin installation/selection to the distribution rather than the Coding-Agent package graph. The Session and delegation behavior below remains in force.

Delegated Sessions currently depend on an application-internal task runtime registration, so a Plugin cannot create and manage Agent Sessions through the same public contract used by Wincode. Wincode will publish a general Session SDK from `@wincode/coding-agent`, modeled on Pi's `createAgentSession` and `SessionManager`. Callers can create or reopen a Session, prompt or continue it, subscribe to events, and dispose its live handle. The caller owns handle cleanup. Model, tools, workspace, storage, and resource loading are configurable; omitted settings resolve from Wincode configuration. The SDK's default tool set includes core coding and shell Plugins. MCP and Subagents are selected explicitly by SDK callers. File-loaded Plugins are included only when their paths have been explicitly enabled in user-controlled Wincode configuration or passed by the caller, never by project discovery.

The Subagents package owns a child-session factory that uses this SDK's generic Session operations to create, open, and dispose child Sessions; it chooses each child's Plugin set and forwards capability ceilings. The package also owns task orchestration and durable task/report records, using its own storage implementation as needed. The host provides general Session operations, including an idempotent delivery operation that accepts a message only after its Session Record commits; it does not expose a delegation-specific runtime port or a generic Plugin storage service. Deliveries use the ordinary FIFO Submission lane: they neither interrupt an active turn nor jump ahead of earlier queued Submissions. This intentionally revises ADR-0035's active-turn report follow-up priority while keeping report messages durable and ordered. Plugin context supplies parent Session identity and public SDK operations, not the application's raw Session object. This revises implementation ownership in ADR-0035.

A child resolves its Agent configuration and Tool Permission independently, as in Pi. There is no mandatory parent permission ceiling. Agent configuration and parent Plugins may provide optional capability ceilings outside model tool arguments; these restrictions intersect with the child's own choices and are snapshotted when the child is created. A ceiling is an allowlist of model-visible tool names: Agent configuration uses `capability_ceiling: { tools: [...] }`, and Session runtime creation uses `capabilityCeiling: { tools: [...] }`. The ceiling filters the child's resolved tools without changing its Agent or Permission configuration, and the Tool Gate denies any actual call outside the snapshot. Delegated tasks retain durable child Session and task identities, explicit `submit_result` acknowledgement, correlated reports, cancellation, and FIFO parent inbox delivery. Normal shutdown cancels active children and reports that outcome, but preserves children already `awaiting_report` so they can explicitly submit their result later. After an unclean shutdown, unconfirmed active work is marked interrupted and durably reported without replaying model or tool work; an operator may explicitly reopen and continue its Session. Interactive and RPC Hosts continue an eligible idle parent with pending reports; Print and JSON leave them pending for explicit continuation. Awaiting-report children are never auto-continued during recovery.

This boundary lets a caller build other Session-based Plugins without adopting Subagents' task model or persistence format. It supersedes ADR-0038's absence of Agent control and its internal `registerSessionDelegationRuntime` arrangement.
