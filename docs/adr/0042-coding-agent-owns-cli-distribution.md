# Coding-Agent owns the CLI distribution

Status: accepted

`@wincode/coding-agent` owns the `wincode` executable and declares `@wincode/mcp` and `@wincode/subagents` as runtime dependencies. Its application entry points select those Plugins by default, as Pi's CLI selects built-in extensions; public Session SDK callers still select Plugin paths explicitly. This removes the redundant `@wincode/cli` wrapper and ensures the module that resolves default Plugin packages declares them as dependencies. The Plugins depend on the public Coding-Agent contract as peers. Coding-Agent does not import Plugin factories or runtime implementations.

The non-TUI `wincode mcp add|remove|list|login|logout` adapter is a narrow exception to that import boundary: the Coding-Agent application layer may call the stable public management API exported by `@wincode/mcp`, but must not import `@wincode/mcp/plugin` or MCP runtime implementation modules. This adapter owns CLI argument parsing, I/O and exit codes, project-trust decisions, and construction of the host capabilities. The MCP management API owns the `mcpServers` configuration shape, validation, resolution, precedence, and MCP diagnostics. It receives namespace-scoped config access, the process environment and workspace needed for MCP resolution, a host-owned write-authorization callback, and the user-scoped secret capability needed for OAuth; generic file access, safe persistence, path confinement, project trust, and secret storage remain host-owned. Dispatch runs MCP management before TUI/runtime startup, without loading unrelated or file-configured Plugins.

This supersedes ADR-0041's separate CLI distribution package decision and its blanket no-import statement only for the public MCP management API described above; the prohibition on importing Plugin factories and runtime implementations remains. It restores ADR-0027's executable boundary.
