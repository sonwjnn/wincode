## Scope and method

This note follows the ownership of five related but different concerns:

1. **Catalog ownership/discovery:** who supplies provider/model IDs and model facts, and whether that source is static, generated, remote, or provider-authenticated.
2. **Variants/reasoning:** how a model declares reasoning capability, effort levels, token budgets, and unsupported levels.
3. **Provider option mapping:** how a user-facing variant becomes an OpenAI/Anthropic/Google/compatible request option.
4. **Usage accounting:** how provider response fields become normalized token buckets at runtime. This is intentionally separate from pricing metadata.
5. **Pricing/metadata synchronization:** where rates and limits come from, how they are cached, and what survives a network failure.

Sources are first-party repositories, first-party source files, and first-party docs/API endpoints only. Existing Wincode research notes were useful for locating paths but are not evidence here. `models.dev` itself distinguishes model-only facts (`models.json`) from provider-serving facts (`api.json`) and offers a combined `catalog.json`; its README also documents TOML `base_model` inheritance for provider entries ([official Models.dev README](https://github.com/anomalyco/models.dev/blob/dev/README.md#L16-L90)). That distinction matters below: a model card/rate card is not the same thing as the runtime adapter that sends a request or parses usage.

> **Reading convention.** “Observed” describes behavior in the cited snapshot. `[Inference]` is a conclusion drawn from those facts. “Recommendation” is a Wincode option, not an upstream claim.

## Wincode baseline

### 1. Catalog authority and IDs are manual

`packages/ai/src/models.ts` defines a closed `connectionProviderIds` union (`openai`, `anthropic`, `google`, `opencode-go`), a separate runtime-provider union, the generic variant union (`none`, `thinking`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`), and the `ModelCatalogEntry` shape (`connectionProviderId`, display name, model ID, runtime provider, route, and variants). The `modelCatalog` array then spells out the supported model rows and display names in source (`packages/ai/src/models.ts:4-73,75-670`). Selection parsing and validation only accept a provider/model pair found in that array (`packages/ai/src/models.ts:681-742`).

The local catalog is therefore the authority for **which model can be selected**, while the metadata feed is not allowed to introduce a new selectable ID. `findSupportedChatModelSelection` returns `null` for an unknown provider/model pair (`packages/ai/src/models.ts:710-724`).

### 2. Variants are split between curated source rows and a generated snapshot

A non-empty `model.variants` array is a manual/curated override. An empty array falls back to `modelVariantsByProviderModel[`${connectionProviderId}/${modelId}`]`, imported from `packages/ai/src/generated/model-variants.generated.ts` (`packages/ai/src/models.ts:748-809`). That generated file says it was produced by `scripts/sync-model-pricing.ts` from `https://models.dev/api.json` and records a 2026-08-08 snapshot (`packages/ai/src/generated/model-variants.generated.ts:1-10`). The current tree has no `scripts/sync-model-pricing.ts`; `model-provider-options.ts` still calls out the deleted pipeline while retaining manual Anthropic and Google budget tables (`packages/ai/src/model-provider-options.ts:137-180`).

The result is two ownership layers:

- model IDs and display names: hand-maintained `modelCatalog`;
- many variant lists and OpenCode Go budget/toggle records: generated models.dev snapshot, unless a curated row overrides them.

The generated example shows different shapes, including an OpenCode Go toggle (`minimax-m3`) and high/max budgets for Qwen models (`packages/ai/src/generated/model-variants.generated.ts:451-563`).

### 3. Provider-option translation is a local compatibility matrix

`model-provider-options.ts` uses a discriminated union for OpenAI, Anthropic, and Google provider options rather than one untyped options bag (`packages/ai/src/model-provider-options.ts:20-76`). The schemas explicitly constrain the wire vocabulary: OpenAI `reasoningEffort`/`reasoningSummary`/`store`, Anthropic adaptive/disabled/enabled thinking with `budgetTokens`, and Google `thinkingBudget`/`thinkingLevel` (`packages/ai/src/model-provider-options.ts:78-135`).

The resolver then consults model-ID tables and maps the generic variant ladder to provider-specific controls:

- OpenAI maps a variant to `reasoningEffort` and may add `reasoningSummary: "detailed"` for a manual list of models (`packages/ai/src/model-provider-options.ts:248-261`).
- Anthropic chooses adaptive thinking for a manual model list, or a manual token budget for other listed models; it caps output at 32,000 and rejects a budget that leaves no answer room (`packages/ai/src/model-provider-options.ts:263-301`).
- Google chooses a thinking level for a manual list, otherwise a manual high/max token budget, with the same output-room check (`packages/ai/src/model-provider-options.ts:303-340`).
- OpenCode Go uses the generated entry's `kind: "toggle"` or `budget` fields to emit Anthropic disabled/adaptive thinking or an enabled token budget; its OpenAI and compatible branches use the OpenAI mapping or no provider options (`packages/ai/src/model-provider-options.ts:347-431`).

**Observed tradeoff:** this is type-safe and deterministic, but model additions or provider protocol changes require either catalog regeneration or edits to hand-maintained tables. The TODO in the source is an explicit sign that the current reasoning-budget ownership is not unified (`packages/ai/src/model-provider-options.ts:157-165`).

### 4. Runtime usage is normalized separately from pricing metadata

`ModelUsage` requires non-negative integer `inputTokens` and `outputTokens`, with optional cache-read/cache-write/reasoning/total fields (`packages/ai/src/model-usage.ts:4-15`). `normalizeModelUsage` accepts AI SDK/provider shapes: nested `inputTokenDetails.cacheReadTokens/cacheWriteTokens`, the older `cachedInputTokens`, and nested or top-level reasoning tokens (`packages/ai/src/model-usage.ts:32-58`). This is runtime response handling; it does not discover a model or fetch a price.

`calculateModelUsageCostUsd` returns `null` when no `ModelCost` exists. With a cost record it subtracts only cache-read tokens from input, prices the remainder at `cost.input`, prices cache-read at `cost.cacheRead ?? cost.input`, and prices output at `cost.output` (`packages/ai/src/model-usage.ts:64-79`). The normalized `cacheWriteTokens` field is not used in that formula. **Observed limitation:** cache-write tokens are retained in the normalized record but have no separate cost term and are not subtracted from input. Whether a particular provider's `inputTokens` includes cache writes is provider-dependent, so this is a potential accounting gap rather than proof of a particular provider overcharge. Reasoning is treated as part of output for context-token display (`getModelContextTokens` is input + output, `packages/ai/src/model-usage.ts:60-62`).

### 5. Pricing is a live, cacheable overlay—not the catalog

The pricing table shape is `Record<provider/model, { contextLimit, cost? }>` and lookup first validates the selection against the manual catalog, then keys by the runtime provider and model ID (`apps/cli/src/modules/model-pricing/model-pricing.ts:9-61`). The parser accepts only the four routed runtime providers, keeps requested model IDs, requires a positive `limit.context`, and extracts `input`, `output`, `cache_read`, and `cache_write`; malformed entries and unrelated providers are dropped (`apps/cli/src/modules/model-pricing/models-dev-response.ts:10-115`).

The default URL is `https://models.dev/api.json`. Fetching requires a successful JSON response, has a five-second timeout, and rejects a successful but sparse table covering less than half of the requested IDs (`apps/cli/src/modules/model-pricing/fetch-model-pricing.ts:4-55`). The source snapshot and the variants snapshot are generated artifacts dated 2026-08-08 (`apps/cli/src/modules/model-pricing/model-pricing-snapshot.generated.ts:1-6`).

At runtime Wincode starts with that bundled snapshot, reads `model-pricing.json` from the user data directory, displays a valid cache immediately whether fresh or stale, and refreshes stale/missing data in the background. The default TTL is 24 hours; offline mode suppresses the network fetch; a single module-level promise coalesces concurrent fetches (`apps/cli/src/modules/model-pricing/context/model-pricing-provider.tsx:19-90`). Cache files are versioned, schema-checked, and malformed files are deleted; stale entries remain usable (`apps/cli/src/modules/model-pricing/model-pricing-cache.ts:14-105`).

**Baseline summary:** Wincode intentionally keeps a strict manual selection contract and uses models.dev as a pricing/context overlay. It has good offline determinism and stale-while-revalidate behavior, but catalog metadata, variant capability, provider-wire translation, runtime usage, and pricing are owned by different tables and snapshots.

## OpenCode

### 1. Catalog ownership and discovery

OpenCode's official docs describe OpenCode as using the AI SDK and Models.dev for 75+ providers, with full IDs in `provider_id/model_id` form ([OpenCode model docs](https://github.com/anomalyco/opencode/blob/e2894562f8ba943d72172d10b727c24d5f650c16/packages/web/src/content/docs/models.mdx#L1-L63)). In the implementation, `packages/core/src/models-dev.ts` defines the accepted provider/model payload shape: provider name/id/env/npm/API, model ID/name/family/release date, capabilities, optional reasoning options, modalities, limits, costs/tiers, status, and experimental modes ([source](https://github.com/anomalyco/opencode/blob/e2894562f8ba943d72172d10b727c24d5f650c16/packages/core/src/models-dev.ts#L25-L145)).

The runtime feed is not fetched directly from `models.dev/api.json` in this snapshot. `ModelsDev` uses `Flag.OPENCODE_MODELS_URL` or `https://models.opencode.ai`, fetches `${source}/api.json`, writes a cache file under OpenCode's global cache directory, and uses a five-minute freshness check ([source](https://github.com/anomalyco/opencode/blob/e2894562f8ba943d72172d10b727c24d5f650c16/packages/core/src/models-dev.ts#L160-L183)). Population order is disk JSON, an embedded `OPENCODE_MODELS_DEV` snapshot, then network unless `OPENCODE_DISABLE_MODELS_FETCH` is set ([source](https://github.com/anomalyco/opencode/blob/e2894562f8ba943d72172d10b727c24d5f650c16/packages/core/src/models-dev.ts#L184-L233)). A background refresh repeats every 60 minutes when fetches are enabled ([source](https://github.com/anomalyco/opencode/blob/e2894562f8ba943d72172d10b727c24d5f650c16/packages/core/src/models-dev.ts#L255-L257)).

This is a **catalog service**, not merely a price lookup. `fromModelsDevModel` materializes provider/model identity, AI SDK npm/id/url, status, capabilities/modalities, limits, release date, and cost; it computes variants from provider-aware reasoning transforms. Experimental modes become additional model IDs with mode-specific cost/options/headers ([source](https://github.com/anomalyco/opencode/blob/e2894562f8ba943d72172d10b727c24d5f650c16/packages/opencode/src/provider/provider.ts#L1217-L1349)).

### 2. Variants and provider option mapping

The feed schema models three reasoning-option forms: effort values, a toggle, or a `budget_tokens` range; it also carries interleaving, modalities, status, limits, and experimental provider bodies ([source](https://github.com/anomalyco/opencode/blob/e2894562f8ba943d72172d10b727c24d5f650c16/packages/core/src/models-dev.ts#L52-L145)). OpenCode converts those facts into named variants. `ProviderTransform.variants` derives provider/model-specific ladders (for example OpenAI effort availability by model generation/release date, Google level or budget variants, and Anthropic adaptive or budget variants) rather than exposing one universal ladder to every provider ([source](https://github.com/anomalyco/opencode/blob/e2894562f8ba943d72172d10b727c24d5f650c16/packages/opencode/src/provider/transform.ts#L573-L775)).

The transform's later branches show the actual request vocabulary: `reasoningEffort`, nested OpenRouter `reasoning.effort`, Z.ai/Qwen/DeepSeek/Together thinking forms, Google `thinkingConfig`, Anthropic `thinking` or Bedrock `reasoningConfig`, and Copilot-specific reasoning options ([source](https://github.com/anomalyco/opencode/blob/e2894562f8ba943d72172d10b727c24d5f650c16/packages/opencode/src/provider/transform.ts#L777-L1088)). It also maps the selected AI SDK npm package to the correct `providerOptions` key (`sdkKey`, [source](https://github.com/anomalyco/opencode/blob/e2894562f8ba943d72172d10b727c24d5f650c16/packages/opencode/src/provider/transform.ts#L40-L75)).

Configuration can add or override variants under a provider/model entry. The config schema has a provider/model map, model API selection, request `variant`, a `variants` array, cost, disabled flag, and limits ([source](https://github.com/anomalyco/opencode/blob/e2894562f8ba943d72172d10b727c24d5f650c16/packages/core/src/config/provider.ts#L1-L60)). During provider assembly OpenCode deep-merges config variants, removes disabled variants, and re-applies generated variants when no custom variants exist ([source](https://github.com/anomalyco/opencode/blob/e2894562f8ba943d72172d10b727c24d5f650c16/packages/opencode/src/provider/provider.ts#L1392-L1402), [source](https://github.com/anomalyco/opencode/blob/e2894562f8ba943d72172d10b727c24d5f650c16/packages/opencode/src/provider/provider.ts#L1565-L1572), [source](https://github.com/anomalyco/opencode/blob/e2894562f8ba943d72172d10b727c24d5f650c16/packages/opencode/src/provider/provider.ts#L1697-L1706)). The user-facing docs show global provider options and custom variants as separate from the catalog ([docs](https://github.com/anomalyco/opencode/blob/e2894562f8ba943d72172d10b727c24d5f650c16/packages/web/src/content/docs/models.mdx#L69-L200)).

### 3. Runtime usage accounting (separate from model pricing)

The shared LLM `Usage` contract deliberately stores inclusive totals and a non-overlapping breakdown: inclusive input (including cache reads/writes), inclusive output (including reasoning), non-cached input, cache-read, cache-write, reasoning, total, and raw provider metadata. Its comments state the provider differences: OpenAI/Gemini/Bedrock report inclusive fields that the mapper decomposes, while Anthropic reports a native non-cached breakdown; Anthropic's API does not expose reasoning separately from output ([source](https://github.com/anomalyco/opencode/blob/e2894562f8ba943d72172d10b727c24d5f650c16/packages/llm/src/schema/events.ts#L1-L76)).

The AI SDK bridge preserves provider usage fields and maps nested AI SDK details into normalized names (`inputTokens`, `outputTokens`, `totalTokens`, reasoning, cache-read, cache-write) at step/finish events ([source](https://github.com/anomalyco/opencode/blob/e2894562f8ba943d72172d10b727c24d5f650c16/packages/opencode/src/session/llm/ai-sdk.ts#L45-L120)). `Session.getUsage` clamps non-finite/negative values, reads cache-write fields from provider metadata when needed, subtracts cache read/write from inclusive input, and exposes visible output as output minus reasoning. It then selects a model cost tier by context tokens and computes the cost ([source](https://github.com/anomalyco/opencode/blob/e2894562f8ba943d72172d10b727c24d5f650c16/packages/opencode/src/session/session.ts#L338-L398)). Provider metadata remains available for audit fields such as Copilot's billed amount ([source](https://github.com/anomalyco/opencode/blob/e2894562f8ba943d72172d10b727c24d5f650c16/packages/opencode/src/session/llm/ai-sdk.ts#L30-L43), [source](https://github.com/anomalyco/opencode/blob/e2894562f8ba943d72172d10b727c24d5f650c16/packages/opencode/src/session/llm/ai-sdk.ts#L100-L120)).

Thus OpenCode keeps runtime usage normalization in the LLM/session path and model costs/limits in the catalog path. The cost shown to the user is a local calculation from catalog rates, not an API billing statement; that distinction is an inference from the fact that `Session.getUsage` multiplies normalized tokens by `model.cost`.

### 4. Pricing source, caching, and fallback

The conversion from Models.dev cost data keeps base `input`/`output`/cache rates, context tiers, and `context_over_200k` pricing ([source](https://github.com/anomalyco/opencode/blob/e2894562f8ba943d72172d10b727c24d5f650c16/packages/opencode/src/provider/provider.ts#L1217-L1245)). Missing cost values default to zero in that conversion ([source](https://github.com/anomalyco/opencode/blob/e2894562f8ba943d72172d10b727c24d5f650c16/packages/opencode/src/provider/provider.ts#L1217-L1225)).

The fallback chain is explicit and local-first: disk cache, embedded snapshot, then network; a disabled fetch returns an empty ModelsDev map ([source](https://github.com/anomalyco/opencode/blob/e2894562f8ba943d72172d10b727c24d5f650c16/packages/core/src/models-dev.ts#L184-L233)). Refresh failures are logged and ignored rather than replacing the last disk file ([source](https://github.com/anomalyco/opencode/blob/e2894562f8ba943d72172d10b727c24d5f650c16/packages/core/src/models-dev.ts#L241-L253)). OpenCode can therefore start offline from disk or the compiled snapshot, while a later refresh updates the catalog without a binary release. The five-minute freshness window and hourly background schedule are catalog synchronization policy, not token accounting policy.

An unknown provider/model is not silently turned into a generic selectable model. `Provider.getModel` returns a typed `ModelNotFoundError` containing fuzzy suggestions, and a provider SDK `NoSuchModelError` is translated to the same error ([source](https://github.com/anomalyco/opencode/blob/e2894562f8ba943d72172d10b727c24d5f650c16/packages/opencode/src/provider/provider.ts#L1137-L1150), [source](https://github.com/anomalyco/opencode/blob/e2894562f8ba943d72172d10b727c24d5f650c16/packages/opencode/src/provider/provider.ts#L1871-L1919)). Deprecated models and, unless enabled, alpha models are filtered during assembly ([source](https://github.com/anomalyco/opencode/blob/e2894562f8ba943d72172d10b727c24d5f650c16/packages/opencode/src/provider/provider.ts#L1697-L1706)).

**OpenCode tradeoff:** a rich remote catalog and short refresh interval provide fast metadata/model updates and provider-aware variants, at the cost of a network/cache service, feed trust, and more merge rules. The embedded snapshot and disk-first loading preserve offline startup.

## Pi

### 1. Catalog ownership and synchronization layers

Pi's generated catalog is provider-sharded. `packages/ai/src/models.generated.ts` imports generated model shards for each built-in provider, while `packages/ai/src/providers/all.ts` exposes typed reads, the generated-at timestamp, and the list of freshly constructed built-in providers ([generated catalog](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/ai/src/models.generated.ts#L1-L100), [provider assembly](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/ai/src/providers/all.ts#L1-L150)). Individual shard files are generated from provider JSON data ([example](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/ai/src/providers/openai.models.ts#L1-L8)).

The build-time generator fetches `https://models.dev/api.json`, filters tool-capable rows, copies limits/cost/modalities, records `reasoning_options`, and applies provider-specific corrections. It also fetches provider catalogs such as OpenRouter and Vercel AI Gateway ([generator](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/ai/scripts/generate-models.ts#L87-L150), [generator](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/ai/scripts/generate-models.ts#L1461-L1641), [generator](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/ai/scripts/generate-models.ts#L2411-L2434)). The generator has explicit corrections and static exceptions; for example, its Codex comment says those rows are not fetched from models.dev and remain an explicit list ([generator](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/ai/scripts/generate-models.ts#L2731-L2734)).

At runtime the generic `Provider` contract owns a synchronous model list and may optionally implement `refreshModels`; `Models.getModels/getModel` read the last-known list, while `createProvider` merges a static baseline with a provider-owned dynamic overlay ([source](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/ai/src/models.ts#L97-L145), [source](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/ai/src/models.ts#L752-L840)). This makes generated model data the normal built-in baseline rather than a runtime dependency on `models.dev`.

There is a second, official Pi runtime catalog layer. Coding-agent wraps most built-in providers with `withRemoteCatalog`, whose default base is `https://pi.dev`; it requests `/api/models/providers/{provider}` and overlays rows returned by that endpoint ([source](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/remote-catalog-provider.ts#L1-L50), [source](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/remote-catalog-provider.ts#L80-L95)). The overlay is accepted only when its stored `lastModified` is newer than the local generated-at time ([source](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/remote-catalog-provider.ts#L34-L44)). A conditional `ETag` request is used when a cached body exists; a `304` advances `checkedAt` without replacing the body, and a failed request keeps the existing in-memory overlay ([source](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/remote-catalog-provider.ts#L80-L128)). The refresh interval is four hours ([source](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/remote-catalog-provider.ts#L7-L8)).

`ModelRuntime.create` stores dynamic catalogs through a file-backed `ModelsStore` (by default alongside the models config), wraps built-ins with the Pi remote catalog, and only permits network refresh when `allowModelNetwork: true` and `PI_OFFLINE` is absent. Static models remain available when refresh is skipped ([source](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/model-runtime.ts#L60-L80), [source](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/model-runtime.ts#L176-L212)). `ModelsStoreEntry` carries the model rows plus `lastModified`, `checkedAt`, and `etag` validators ([source](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/ai/src/models-store.ts#L1-L35)).

**Answer to “does Pi fetch models.dev at runtime?”** The built-in catalog is generated from models.dev, but this Pi snapshot's runtime overlay is the official `pi.dev` provider endpoint, not a direct `models.dev/api.json` request. A caller can disable/omit runtime network refresh and still use generated static rows and any eligible cached overlay.

### 2. Variants/reasoning and provider option mapping

Pi's model type carries provider/API ID, display name, reasoning boolean, input modalities, context window, max output, per-million cost, optional tiered cost, `thinkingLevelMap`, and provider compatibility overrides ([source](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/ai/src/types.ts#L825-L866)). `ThinkingLevelMap` is tristate: a string remaps a generic level, `null` hides it, and an omitted `xhigh`/`max` remains unsupported; `getSupportedThinkingLevels` and `clampThinkingLevel` implement those rules ([source](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/ai/src/types.ts#L84-L86), [source](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/ai/src/models.ts#L920-L964)).

The provider compatibility shape covers sampling and protocol translation, including `supportsDeveloperRole`, `supportsReasoningEffort`, `maxTokensField`, `thinkingFormat`, chat-template arguments, token-budget fields, cache controls, and routing ([source](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/ai/src/types.ts#L550-L705)). The OpenAI-compatible adapter demonstrates the mapping: it clamps a requested generic reasoning level, then emits Z.ai, Qwen, Qwen chat-template, DeepSeek, OpenRouter, Together, string-thinking, or ordinary OpenAI `reasoning_effort` fields according to the resolved compatibility mode and model map ([source](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/ai/src/api/openai-completions.ts#L736-L744), [source](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/ai/src/api/openai-completions.ts#L863-L971)). Thinking budgets are independently clamped to leave answer room ([source](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/ai/src/api/openai-completions.ts#L997-L1059)).

Custom `~/.pi/agent/models.json` rows use the same contract. The official docs define defaults (`reasoning: false`, `contextWindow: 128000`, `maxTokens: 16384`, zero costs), `thinkingLevelMap`, per-million cost tiers, provider/model APIs, and provider/model compatibility settings; the file reloads when `/model` opens ([docs](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/docs/models.md#L1-L120), [docs](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/docs/models.md#L200-L360)).

### 3. Runtime usage and pricing

Pi's runtime `Usage` record separates non-cached `input`, `output` (including thinking), `cacheRead`, `cacheWrite`, optional `reasoning`, `totalTokens`, and per-bucket `cost`; `reasoning` is optional because not every provider exposes it ([source](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/ai/src/types.ts#L383-L410)). The OpenAI-compatible parser accepts several provider placements for cache hits (`prompt_tokens_details.cached_tokens`, `prompt_cache_hit_tokens`, top-level `cached_tokens`) and separate cache writes, computes non-cached input with a non-negative clamp, treats `completion_tokens` as output including reasoning, and invokes `calculateCost` ([source](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/ai/src/api/openai-completions.ts#L1508-L1547)).

`calculateCost` selects the highest matching request-wide input tier, prices each normalized bucket, and applies Anthropic's one-hour cache-write multiplier separately from short writes ([source](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/ai/src/models.ts#L891-L919)). This is **runtime accounting** based on the selected model's stored rate card; it is not the same operation as refreshing the card.

### 4. Fallback, unknown IDs, and pricing freshness

Pi's exact resolver prefers a canonical `provider/modelId`, rejects ambiguous bare IDs, and then uses alias/date-aware fuzzy matching ([source](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/model-resolver.ts#L76-L170)). There are two different unknown-model behaviors:

- `ModelRuntime.getModel(provider, id)` only finds a last-known model in the provider list.
- CLI/model-scope resolution can deliberately construct a fallback model by cloning a provider's default/first model and replacing its ID/name; a requested thinking level can set `reasoning: true` on that synthesized row ([source](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/model-resolver.ts#L174-L187), [source](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/model-resolver.ts#L571-L592)). **[Inference]** This permits custom/unknown IDs for a provider that already has a baseline, but inherited limits/costs should not be mistaken for authoritative metadata.

For custom provider command-resolved secrets, Pi explicitly declines to infer a universal cache/TTL/recovery policy: command values run at request time, and the docs recommend that users wrap expensive or failure-prone commands themselves. `/model` availability checks use configured auth presence and do not execute those commands ([docs](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/docs/models.md#L120-L190)).

**Pi tradeoff:** generated model shards make normal startup deterministic and avoid a mandatory metadata network call. The optional `pi.dev` overlay gives fresher IDs/limits/costs, but requires an additional synchronization service and validator-aware cache. Custom models remain powerful and explicit, while unknown-ID fallback favors usability over guaranteed metadata accuracy.

## Oh My Pi (OMP)

### 1. Catalog ownership and discovery

OMP identifies itself as a Pi fork in its official README ([README](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/README.md#L20-L24), whose repository metadata reports a separate repository), but its catalog is a separately packaged subsystem. `@oh-my-pi/pi-catalog` describes itself as the bundled model database, provider discovery descriptors, identity/classification, and equivalence package; its package manifest exports the model, provider-model, discovery, identity, compat, cache, and manager modules ([catalog package](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/packages/catalog/package.json#L1-L35), [catalog exports](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/packages/catalog/src/index.ts#L1-L16)). The static registry intentionally contains compile-time defaults only; it does not include runtime discovery, shared-catalog overlays, or on-disk cache state ([static registry](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/packages/catalog/src/models.ts#L1-L16)).

The build generator has three materially different input classes:

- a shared catalog loaded by `fetchWellKnownModels`;
- credentialed provider model managers, fetched only when credentials exist or the descriptor allows unauthenticated discovery;
- local/self-hosted and credential-scoped providers that are deliberately not bundled.

The generator names the local discovery-only set (`ollama`, `vllm`, `lm-studio`, `litellm`), the credential-scoped `devin` set, resolves env/auth-storage credentials, and uses a provider manager with stale-cache fallback for build-time discovery ([generator](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/packages/catalog/scripts/generate-models.ts#L85-L195)). It loads the shared `stencil.so` catalog and maps it into model specs ([generator](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/packages/catalog/scripts/generate-models.ts#L184-L195)), excludes the discovery-only/credential-scoped sets from the generated bundle, and merges provider snapshots and curated fallback rows with explicit precedence ([generator](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/packages/catalog/scripts/generate-models.ts#L488-L550), [generator](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/packages/catalog/scripts/generate-models.ts#L632-L690)).

The shared source is a field-pruned, zstd-compressed catalog endpoint at `https://catalog.stencil.so/models.json.zstd`. OMP's source comments call it the models.dev catalog; the client sends conditional requests using an in-memory ETag, accepts `304`, decompresses zstd or plain JSON, and reuses the last in-memory payload after transient errors ([catalog client](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/packages/catalog/src/provider-models/openai-compat.ts#L65-L185), [catalog request](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/packages/catalog/src/provider-models/openai-compat.ts#L210-L260)). This is not evidence that the endpoint is byte-for-byte identical to `https://models.dev/api.json`; it is evidence of OMP's chosen catalog transport and naming.

### 2. Runtime merge, cache, and authority policy

OMP's reusable `ModelManager` accepts bundled/static models, an optional `modelsDev` fallback hook, an optional provider endpoint fetcher, and a `dynamicModelsAuthoritative` flag. It reports `source` as `bundled`, `cache`, `models.dev`, or `provider`, plus `stale` and `updatedAt`; its default cache TTL is two hours and its refresh strategies are `online`, `offline`, and `online-if-uncached` ([manager](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/packages/catalog/src/model-manager.ts#L8-L88)).

The source precedence is explicit: static → cached fallback → stencil.so/models.dev → dynamic provider endpoint, with later rows overriding by model ID ([manager](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/packages/catalog/src/model-manager.ts#L183-L242)). A fresh authoritative cache can bypass the network; failed remote resolution leaves usable cache rows visible and marks the result stale; a successful authoritative provider fetch can prune static-only IDs, whereas the shared catalog is additive ([manager](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/packages/catalog/src/model-manager.ts#L244-L319)). The merge retains provider/model IDs and rebuilds models through the catalog policy layer; discovery values can replace limits/costs where valid, while static metadata remains the fallback ([manager](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/packages/catalog/src/model-manager.ts#L319-L455)).

The cache is SQLite-backed and stores model specs rather than arbitrary request headers. Its schema includes a version, freshness timestamp, authoritative flag, static fingerprint, and header-restore markers; rows are invalidated across schema versions and malformed/corrupt databases are healed ([cache](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/packages/catalog/src/model-cache.ts#L1-L50), [cache](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/packages/catalog/src/model-cache.ts#L80-L120), [cache](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/packages/catalog/src/model-cache.ts#L200-L300)). Static fingerprints let a fresh cache return the already-merged static+dynamic result without repeating the merge.

The official docs summarize the same contract: bundled rows are startup/offline baseline; background refresh can add newly published IDs and current limits/pricing/modalities/capability flags; remote shared rows cannot introduce code, arbitrary headers, or an unregistered provider; fresh cache avoids a network request; failed refresh keeps stale cache or falls back to bundled data ([OMP model docs](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/docs/models.md#L170-L210)).

### 3. Reasoning metadata and provider option translation

OMP puts canonical reasoning capability in a built model rather than making request handlers infer it. `ThinkingConfig` records the control mode (`effort`, `budget`, Google level, Anthropic adaptive, or Anthropic budget/effort), ordered user-facing efforts, optional default, effort-to-wire map, per-effort model routing, per-effort token budgets, explicit suppression when thinking is off, and mandatory-effort behavior ([types](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/packages/catalog/src/types.ts#L26-L87)).

The OpenAI-compatible compatibility shape separately records provider protocol facts such as `supportsReasoningEffort`, `reasoningEffortMap`, `maxTokensField`, `thinkingFormat`, reasoning-disable mode, response replay fields, cache behavior, and routing ([types](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/packages/catalog/src/types.ts#L190-L230)). Resolved compatibility fields are materialized once, including the resolved thinking format and effort map ([types](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/packages/catalog/src/types.ts#L638-L705)). `buildModel` invokes the compatibility policy and applies catalog assignments/corrections to cost, limits, modalities, context promotion, and wire policy before request handling ([build](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/packages/catalog/src/build.ts#L1-L35), [build](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/packages/catalog/src/build.ts#L80-L140), [build](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/packages/catalog/src/build.ts#L200-L290)).

This lets OMP support provider-specific controls while preserving a generic effort selector. The docs expose the same distinction to users: `reasoning`, `thinkingLevelMap`/thinking metadata, model-level `compat`, provider-level defaults, and model overrides are separate fields ([docs](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/docs/models.md#L40-L112), [docs](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/docs/models.md#L200-L230)).

### 4. Runtime usage versus pricing

OMP's `Usage` type is broader than Wincode's normalized record: non-cached input, output, cache read/write, total, authoritative context tokens, provider-side orchestration buckets, premium requests, optional reasoning subset, Anthropic cache TTL breakdown, server tools, credits, and the computed cost object ([types](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/packages/catalog/src/types.ts#L96-L160)). `reasoningTokens` is explicitly optional/unknown rather than guessed as zero.

`calculateUsageCost` prices model usage using the model's rate card, includes orchestration input/cache/output when determining the active context tier, and prices conversation/orchestration buckets separately. Cache writes honor 5-minute/one-hour Anthropic TTL components and price any unattributed residual at the short-write rate instead of silently making it free ([models](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/packages/catalog/src/models.ts#L50-L110)). This is a runtime calculation after a provider adapter has normalized response usage; it does not itself discover prices.

The model rate card can carry long-context costs, catalog corrections, and provider-specific patches. `applyCatalogCorrections` applies reviewed cost/limit/modalities corrections over an upstream-sourced spec while allowing explicit user values to win ([build](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/packages/catalog/src/build.ts#L45-L140)). **[Inference]** OMP's separation of catalog correction and usage calculation makes it possible to distrust or revise a rate source without changing the wire usage parser.

### 5. Unknown/offline behavior and tradeoff

The manager rejects malformed model rows during normalization and only materializes valid model specs. Unknown provider IDs cannot gain runtime code or arbitrary headers from a shared metadata row; provider descriptors and registered adapters remain the authority. The shared catalog is additive, while endpoint discovery can be authoritative ([docs](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/docs/models.md#L194-L198)). OMP's LiteLLM documentation explicitly warns that fallback IDs absent from the bundled catalog can have unknown context and pricing ([docs](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/docs/models.md#L250-L268)). Local unknown models can still use the fast local tokenizer estimate when no known identity exists ([docs](https://github.com/can1357/oh-my-pi/blob/65f79e76fcc89b96632fe86a598f314bd7cfc725/docs/models.md#L110-L112)).

**OMP tradeoff:** it invests in the richest layered system here—generated bundle, provider descriptors, credential-aware endpoint discovery, additive shared catalog, authoritative dynamic providers, SQLite stale cache, static fingerprints, catalog corrections, and one-time compat materialization. That supports rapid model updates and local/provider discovery, but has more merge/authority/security semantics than Pi's mostly generated static baseline or Wincode's strict catalog plus price overlay.

## Is manual `models.dev` fetching necessary?

**Not as a general catalog requirement.** The three upstream designs demonstrate three viable contracts:

1. **OpenCode:** runtime shared catalog with a disk cache and embedded snapshot. It can show newly published metadata/models without a binary release, but pays for feed/cache/merge complexity.
2. **Pi:** build-time models.dev generation for deterministic built-ins, plus an optional official Pi.dev overlay with validators and opt-in network refresh. Direct runtime `models.dev/api.json` fetching is not required for its normal built-in path.
3. **OMP:** generated static bundle plus runtime shared-catalog/provider managers, with explicit additive versus authoritative rules and a SQLite stale cache. It uses a compressed catalog transport and provider endpoint discovery rather than relying on one raw API call.

For Wincode, direct manual fetching is necessary only if the product contract is **“this installed binary should refresh live cost/context metadata for its fixed supported IDs.”** If that contract is relaxed, Wincode can preserve its strict model-selection boundary while either pinning metadata at build time (Pi-like) or introducing a catalog manager that overlays known IDs and keeps a bundled snapshot (OpenCode/OMP-like).

### Concrete Wincode options (recommendations, not upstream facts)

1. **Keep the closed catalog; simplify source ownership.** Treat `modelCatalog` as the security/product allowlist and treat remote metadata as an optional `provider/model` overlay. Keep current snapshot-first behavior. This preserves deterministic selection and avoids letting a remote feed add an executable provider or model.
2. **Restore a build-time generator if live refresh is not required.** Generate one validated artifact containing limits, costs, capabilities, and reasoning options from a pinned source, then apply a small reviewed correction file for provider-specific exceptions. This removes startup network/cache code, but updates become release/CI work and freshness is bounded by releases.
3. **If live freshness is required, adopt a small manager—not a second manual table.** Use source precedence `bundled → validated cache → remote`, explicit TTL/stale status, a per-source/provider key, and additive-only behavior for remote model rows. Never let remote metadata supply provider code, headers, or a new runtime adapter. This borrows the useful boundary from OMP while retaining Wincode's strict selection allowlist.
4. **Move variant capability into the same metadata record as limits/cost.** A single per-provider/model record can own `reasoning`, supported efforts, token budgets, and wire dialect. Keep provider-specific request option builders typed; do not send raw remote options directly to the SDK. This removes the current split between generated variants and manual budget tables.
5. **Keep usage normalization independent.** Preserve provider adapters/AI SDK usage parsing as runtime code and pass a normalized record to accounting. Separately version/correct the rate card. In particular, decide whether cache-write tokens are inclusive in `inputTokens`; then either add a cache-write rate term or explicitly document that writes are intentionally estimated at another rate. The current `calculateModelUsageCostUsd` leaves that bucket unpriced.
6. **Add provider-owned discovery only for providers Wincode actually supports.** For local/custom OpenAI-compatible endpoints, a `/models` or provider-specific discovery manager can be more useful than a global models.dev fetch. Discovery should return a valid typed model spec, preserve the provider/model identity, and fall back to static/custom rows when unavailable.

## Limitations and snapshot notes

- This is a source snapshot, not a claim that upstream behavior will remain stable. OpenCode was read at `e2894562...` (2026-09-05), Pi at `853a80d...` (2026-08-28), and OMP at the requested pinned `65f79e...` (2026-08-31). OMP's current head may differ; the note deliberately uses the pinned commit for reproducibility.
- Models.dev and its mirrors/catalog transports can change independently of these repositories. The official Models.dev README documents multiple payloads (`api.json`, `models.json`, `catalog.json`), while each upstream chooses its own endpoint/cache policy.
- Provider billing can differ from a public rate card or a locally calculated estimate. The usage sections describe normalization and local multiplication, not provider invoices.
- The note does not claim every Pi or OMP provider has dynamic discovery. It records the extension points and the built-in/catalog paths observed in the cited snapshots; individual provider descriptors determine whether a remote endpoint is used.
- “Unknown model” is not one universal state: Wincode rejects unknown selections; OpenCode returns a typed not-found error; Pi's CLI resolver can synthesize a provider-baseline fallback; OMP's LiteLLM path documents unknown context/pricing for IDs absent from its bundled references.
