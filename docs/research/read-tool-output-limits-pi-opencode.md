## Conclusion

**Verified:** OpenCode caps read output at **50 KiB of UTF-8 bytes** (`MAX_BYTES = 50 * 1024`, labeled "50 KB"), a default of **2000 lines** (`DEFAULT_READ_LIMIT = 2000`), and truncates any single line over **2000 characters** (`MAX_LINE_LENGTH = 2000`, JS string code units). Bytes are counted per line as `Buffer.byteLength(line, "utf-8") + 1` newline separator; the `N: ` line-number prefix is appended *after* budgeting, so the returned payload can exceed 50 KiB by the numbering prefixes. Directory reads are capped only by the 2000-entry line limit, not by bytes. ([constants](https://github.com/anomalyco/opencode/blob/03bba464d46f3eddf74195919b1344aa937f7b11/packages/opencode/src/tool/read.ts#L13-L18), [byte accounting](https://github.com/anomalyco/opencode/blob/03bba464d46f3eddf74195919b1344aa937f7b11/packages/opencode/src/tool/read.ts#L162-L164), [default limit](https://github.com/anomalyco/opencode/blob/03bba464d46f3eddf74195919b1344aa937f7b11/packages/opencode/src/tool/read.ts#L266), [post-budget numbering](https://github.com/anomalyco/opencode/blob/03bba464d46f3eddf74195919b1344aa937f7b11/packages/opencode/src/tool/read.ts#L339), [notice](https://github.com/anomalyco/opencode/blob/03bba464d46f3eddf74195919b1344aa937f7b11/packages/opencode/src/tool/read.ts#L344-L347), [description](https://github.com/anomalyco/opencode/blob/03bba464d46f3eddf74195919b1344aa937f7b11/packages/opencode/src/tool/read.txt#L5-L11))

**Verified:** Pi caps read output at **2000 lines or 50 KB** (`DEFAULT_MAX_LINES = 2000`, `DEFAULT_MAX_BYTES = 50 * 1024` in shared truncation utilities), whichever is hit first. The budget is UTF-8 bytes (`Buffer.byteLength(line, "utf-8") + 1` newline per line) and never returns partial lines; a single line larger than the budget is a special error state that suggests a `bash sed -n` fallback. A user-supplied `limit` is honored before truncation. Pi has **no per-line character cap** for read (grep match lines use a separate 500-char cap). ([constants](https://github.com/earendil-works/pi/blob/a470b121bf683b4c2b9fc0b3a7c807de7e0cfe9c/packages/coding-agent/src/core/tools/truncate.ts#L11-L13), [first-line-exceeds](https://github.com/earendil-works/pi/blob/a470b121bf683b4c2b9fc0b3a7c807de7e0cfe9c/packages/coding-agent/src/core/tools/truncate.ts#L105-L117), [byte accounting](https://github.com/earendil-works/pi/blob/a470b121bf683b4c2b9fc0b3a7c807de7e0cfe9c/packages/coding-agent/src/core/tools/truncate.ts#L128-L138), [read wiring](https://github.com/earendil-works/pi/blob/a470b121bf683b4c2b9fc0b3a7c807de7e0cfe9c/packages/coding-agent/src/core/tools/read.ts#L218), [truncate call](https://github.com/earendil-works/pi/blob/a470b121bf683b4c2b9fc0b3a7c807de7e0cfe9c/packages/coding-agent/src/core/tools/read.ts#L295))

**Verified locally:** Wincode does **not** consume either upstream read tool and does not override their constants — it implements its own read tool in `packages/ai` with a much smaller cap: **6000 UTF-8 bytes** (`READ_CONTENT_MAX_BYTES = 6000`). Unlike both upstreams, the `N: ` line-number prefix is counted inside the budget, and the continuation-notice bytes are reserved inside the budget before each line is accepted. Truncation returns a `path:N-M` line-range selector instead of an `offset` hint; a single line over 6000 bytes is a hard error. ([constant](https://github.com/sonwjnn/wincode/blob/46bd09b9f1e1aed6cb6e8103e2be6646c3adfe98/packages/ai/src/tools/read/runner.ts#L11), [byte accounting](https://github.com/sonwjnn/wincode/blob/46bd09b9f1e1aed6cb6e8103e2be6646c3adfe98/packages/ai/src/tools/read/runner.ts#L232-L264), [continuation notice](https://github.com/sonwjnn/wincode/blob/46bd09b9f1e1aed6cb6e8103e2be6646c3adfe98/packages/ai/src/tools/read/runner.ts#L118-L130), [errors](https://github.com/sonwjnn/wincode/blob/46bd09b9f1e1aed6cb6e8103e2be6646c3adfe98/packages/ai/src/tools/read/runner.ts#L273-L285))

**Byte vs character semantics:** all three budgets are measured in **UTF-8 bytes** (`Buffer.byteLength`), not characters. OpenCode is the only one with a separate per-line cap, and it is character-based (2000 JS string code units via `.length`/`.substring` — up to 8000 bytes on astral text). Pi's read tool has no per-line cap; its grep tool truncates lines to 500 characters (`GREP_MAX_LINE_LENGTH`). Wincode's read tool has no character cap at all.

## OpenCode trace

1. Constants at the top of the tool: `DEFAULT_READ_LIMIT = 2000`, `MAX_LINE_LENGTH = 2000`, `MAX_BYTES = 50 * 1024`, `SAMPLE_BYTES = 4096` (binary sniffing). ([source](https://github.com/anomalyco/opencode/blob/03bba464d46f3eddf74195919b1344aa937f7b11/packages/opencode/src/tool/read.ts#L13-L18))
2. The streaming `lines` reader truncates each line to 2000 chars, then counts `Buffer.byteLength(line, "utf-8") + 1` per line (newline separator) and stops the stream once the byte cap is reached. Hitting the line `limit` sets `more`; hitting bytes sets `cut`; both stop early. ([per-line cut](https://github.com/anomalyco/opencode/blob/03bba464d46f3eddf74195919b1344aa937f7b11/packages/opencode/src/tool/read.ts#L162), [byte cap](https://github.com/anomalyco/opencode/blob/03bba464d46f3eddf74195919b1344aa937f7b11/packages/opencode/src/tool/read.ts#L163-L167))
3. `params.limit ?? DEFAULT_READ_LIMIT` supplies the default 2000 lines; the `N: ` numbering prefix is added when rendering, after budgeting, so it escapes the byte count. ([default](https://github.com/anomalyco/opencode/blob/03bba464d46f3eddf74195919b1344aa937f7b11/packages/opencode/src/tool/read.ts#L266), [numbering](https://github.com/anomalyco/opencode/blob/03bba464d46f3eddf74195919b1344aa937f7b11/packages/opencode/src/tool/read.ts#L339))
4. Byte truncation appends `(Output capped at 50 KB. Showing lines X-Y. Use offset=N to continue.)`; line-limit truncation appends `(Showing lines X-Y of N. Use offset=N to continue.)`. ([source](https://github.com/anomalyco/opencode/blob/03bba464d46f3eddf74195919b1344aa937f7b11/packages/opencode/src/tool/read.ts#L344-L347))
5. The model-facing `read.txt` documents the line and character limits, but not the byte cap. ([source](https://github.com/anomalyco/opencode/blob/03bba464d46f3eddf74195919b1344aa937f7b11/packages/opencode/src/tool/read.txt#L5-L11))
6. `dev` head (default branch) on 2026-08-29 has identical constants at the same locations.

## Byte vs character semantics

- All three implementations measure their **total** budget in UTF-8 bytes via `Buffer.byteLength`; multibyte characters count their encoded length (1-4 bytes), not one unit.
- OpenCode's per-line cap is the only character-based limit: 2000 JS string code units (`text.length` / `text.substring`), i.e. up to 2000 astral characters at 4 bytes each (8000 bytes) or 2000 BMP characters (4000-6000 bytes). The description calls it "characters".
- Pi has no per-line cap for read; `truncateLine` (grep match lines) uses a 500-character cap.
- Wincode has no character cap; byte count includes the numbering prefix, so the effective content budget is smaller than 6000 bytes on multi-digit line numbers.

## Uncertainties and limits

- These are source-pinned findings at the stated revisions; no runtime experiments were performed (assignment requested source/docs research only).
- OpenCode's actual returned payload can exceed 50 KiB because the `N: ` numbering prefixes are appended after budgeting — worst case roughly 2000 lines × up to 7 prefix bytes ≈ 14 KiB over budget. The line/byte caps themselves are exact.
- Pi appends its continuation notice after the truncated content, so the final text can exceed 50 KB by the notice length (its own accounting stops at the content).
- OpenCode's `tool.execute.before` plugin hook can alter arguments; this note describes maintained built-in behavior. Pi SDK embeddings may inject remote `ReadOperations`, but truncation constants are shared and unchanged. ([Pi contract](https://github.com/earendil-works/pi/blob/a470b121bf683b4c2b9fc0b3a7c807de7e0cfe9c/packages/coding-agent/src/core/tools/read.ts#L48-L56))
- "50 KB" in OpenCode's notice is a decimal label for 51200 bytes (50 × 1024); Pi renders the same budget as `50.0KB` via `formatSize`.
- Wincode is an independent implementation, not a fork of either upstream; there are no upstream constants to inherit, so "override" does not apply — the comparison is against its own `READ_CONTENT_MAX_BYTES`.
