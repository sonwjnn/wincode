## Terminology and method

This note uses **user configuration** for durable knobs such as whether automatic compaction is enabled, the reserve, the recent-token budget, and the strategy/threshold. It uses **runtime compaction state** for the generated summary, cut/boundary, preserved context, and the in-memory active message list. A session file or database row can therefore be durable without being a configuration source.

“Per-agent” is used narrowly here to mean a setting namespace keyed by a named agent/model role. A directory called an **agent directory** is instead treated as a user/profile-wide storage root unless the source explicitly keys a value by agent identity. A separate `Settings`/`SettingsManager` object supplied by an embedding is an in-memory object scope, not evidence of a persisted per-agent setting.

## Conclusion

**Pi and OMP both persist compaction configuration outside the conversation session.** In Pi, the persistent sources are one global JSON file and one trusted project JSON file. In OMP, they are a global YAML file (plus legacy compatibility sources), a project settings layer, optional one-shot config overlays, and non-persistent runtime overrides. Neither source tree defines a persisted compaction-settings record keyed by session id or named agent id. ([Pi settings types and paths](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/settings-manager.ts#L13-L16), [Pi storage](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/settings-manager.ts#L213-L222); [OMP settings scope](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/docs/settings.md#L13-L26), [OMP schema](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/config/settings-schema.ts#L2492-L2690))

**Both persist the result of compaction per session, separately from those settings.** Pi appends a `CompactionEntry` to a JSONL session file. OMP appends a `CompactionEntry` to its JSONL session file. Wincode likewise stores a compaction row keyed by `session_id` in the local SQLite database. Those entries drive context reconstruction on resume; they do not capture the setting override that caused the compaction. ([Pi entry and context reconstruction](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/session-manager.ts#L69-L79), [Pi append/persist](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/session-manager.ts#L1016-L1043); [OMP entry type](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/session/session-entries.ts#L67-L91), [OMP append path](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/session/session-manager.ts#L1169-L1194); [Wincode schema](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/modules/conversations/storage/schema.ts#L25-L48))

**The current Wincode UI is different.** Wincode has global/project file configuration, but its `/compaction` view currently writes only an in-memory `auto` override into the mounted `ChatView`/`useChat` instance. It makes no settings-store write and no session-row write. Reopening or remounting a conversation restores its durable compaction entries, but not that UI override. ([dialog exposes only `auto`](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/modules/conversations/compaction/compaction-settings-dialog.tsx#L10-L24), [view-local override](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/modules/conversations/ui/views/chat-view.tsx#L94-L118), [override update/reset](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/modules/conversations/ui/views/chat-view.tsx#L276-L290), [hook ref](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/modules/conversations/hooks/use-chat.ts#L401-L407))

### Scope matrix

| Question | Pi | OMP | Wincode at the inspected revision |
|---|---|---|---|
| **Global persisted config** | Yes: `<agentDir>/settings.json`, normally `~/.pi/agent/settings.json`. | Yes: `~/.omp/agent/config.yml` (or existing `config.yaml`); the active agent/profile directory can be relocated. | Yes, read-only config sources under `${XDG_CONFIG_HOME:-~/.config}/wincode` and `~/.wincode`. |
| **Project persisted config** | Yes: `<cwd>/.pi/settings.json`, loaded only when project trust permits it. | Yes: `<cwd>/.omp/config.yml` plus legacy `.omp/settings.json`; native project discovery is scoped to the process cwd. | Yes: project/workspace `wincode.json(c)` and `.wincode/wincode.json(c)` sources; project roots are discovered by the local root helper. |
| **Per-agent persisted config** | No agent-id dimension in `CompactionSettings` or `SettingsManager`; an embedding can supply a separate manager object, but files are global/project. | No named-agent dimension in the compaction schema; an active profile/agent directory is a separate global namespace, not a session/agent-role record. | No agent-id dimension in `CompactionSettings`; the resolver accepts config and session overrides only. |
| **Per-session persisted config knob** | No. The session stores compaction output/boundaries, not settings. | No. The session stores compaction output/boundaries, not settings. | No. The local `conversation_session` and `conversation_compaction` schema has no compaction-settings column; UI overrides are refs/state only. |
| **In-memory runtime override** | `SettingsManager.applyOverrides()` overlays the loaded settings without writing a file. | `Settings.#overrides`/`override()` is explicitly non-persistent; CLI/config overlays are also process-only. | `sessionOverrides` are applied after file config; the current UI keeps them in `ChatView`/`useChat` memory. |
| **Compaction result/state** | Per JSONL session file under the sessions directory, unless `SessionManager.inMemory()`/`--no-session` is used. | Per JSONL session file under the sessions directory, unless `SessionManager.inMemory()` is used. | Per SQLite conversation/session row under the local database path. |

## Pi

### Durable configuration paths

Pi derives the config directory name from the package (`.pi` by default) and allows the agent and session roots to be overridden by `${APP_NAME}_CODING_AGENT_DIR` and `${APP_NAME}_CODING_AGENT_SESSION_DIR` (normally `PI_CODING_AGENT_DIR` and `PI_CODING_AGENT_SESSION_DIR`). `getAgentDir()` defaults to `~/.pi/agent`; `getSettingsPath()` is `<agentDir>/settings.json`; and `getSessionsDir()` is `<agentDir>/sessions`. ([`config.ts`: package/config names and environment variables](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/config.ts#L499-L505), [agent/settings/session paths](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/config.ts#L523-L569))

`FileSettingsStorage` resolves exactly two settings files for a manager: the global `<agentDir>/settings.json` and the project `<resolvedCwd>/.pi/settings.json`. `SettingsManager.create()` records those same paths for diagnostics. The storage implementation uses the supplied `cwd` and `agentDir`; there is no session id in either path. ([`FileSettingsStorage` constructor](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/settings-manager.ts#L213-L222), [`SettingsManager.create`](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/settings-manager.ts#L336-L347))

The compaction-specific persistent fields are `enabled`, `reserveTokens`, and `keepRecentTokens`. Their documented/default values are `true`, `16384`, and `20000`, respectively. ([`CompactionSettings`](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/settings-manager.ts#L13-L16), [core compaction defaults](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/compaction/compaction.ts#L123-L132))

### Loading, merge order, trust, and writes

`SettingsManager.fromStorageWithPaths()` loads the global file and then the project file; `loadFromStorage()` returns an empty project layer when `projectTrusted` is false. The constructor builds the effective settings by deep-merging global then project, so project fields win while nested objects merge recursively. ([load order](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/settings-manager.ts#L356-L380), [project trust gate](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/settings-manager.ts#L393-L400), [deep-merge function](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/settings-manager.ts#L171-L174), [constructor merge](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/settings-manager.ts#L321-L334))

At the API level, Pi's configuration precedence is therefore:

```text
built-in compaction defaults  <-  global settings.json  <-  trusted project .pi/settings.json  <-  applyOverrides()
```

The first three layers are loaded by `SettingsManager`; `applyOverrides()` deep-merges an additional in-memory layer over the current effective settings and does not call a persistence method. A later `reload()` rebuilds the effective value from the two files, so callers should treat `applyOverrides()` as runtime state, not durable configuration. ([`applyOverrides`](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/settings-manager.ts#L522-L552), [reload rebuild](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/settings-manager.ts#L522-L548))

The built-in `setCompactionEnabled()` mutates `globalSettings.compaction.enabled`, marks the global nested field modified, and calls `save()`. Thus Pi's built-in compaction-enabled setter writes the global settings file, not the project file. A project value can still mask that global value because project precedence is higher. ([setter](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/settings-manager.ts#L829-L839), [global save path](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/settings-manager.ts#L620-L670), [Pi README settings scope](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/README.md#L285-L304))

Project trust is a separate global trust decision, not a third compaction scope. The CLI creates a bootstrap settings manager before resolving project trust and later creates a runtime manager with the resolved `projectTrusted` value. Untrusted project settings are consequently absent from the effective compaction configuration. ([bootstrap/runtime managers](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/main.ts#L580-L582), [runtime manager after trust](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/main.ts#L724-L735))

### Runtime use versus persisted session state

`AgentSessionConfig` receives a `SettingsManager`; the `AgentSession` stores it and reads `getCompactionSettings()` when checking a threshold or preparing a manual compaction. The pure `shouldCompact()` function only receives the resolved settings and compares context usage with `contextWindow - reserveTokens`; it does not load or write settings itself. ([`AgentSessionConfig`](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/agent-session.ts#L201-L205), [manager ownership](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/agent-session.ts#L303-L315), [threshold check](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/agent-session.ts#L544-L555), [manual preparation](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/agent-session.ts#L1940-L1957), [`shouldCompact`](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/compaction/compaction.ts#L234-L237))

A compaction preparation carries the resolved settings only as part of the operation input. `prepareCompaction()` computes the current context and cut point, uses `keepRecentTokens`, and returns the settings with the preparation; it does not turn those settings into a session entry. ([`CompactionPreparation` and `prepareCompaction`](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/compaction/compaction.ts#L745-L778), [preparation return](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/compaction/compaction.ts#L810-L828))

The compaction result is instead an append-only session entry. `CompactionEntry` stores the generated `summary`, `firstKeptEntryId`, `tokensBefore`, optional usage, and extension details. `SessionManager.appendCompaction()` appends that entry; `_appendEntry()` calls `_persist()`, which writes to the active JSONL file when persistence is enabled. ([`CompactionEntry`](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/session-manager.ts#L69-L79), [`appendCompaction`](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/session-manager.ts#L1097-L1121), [`_appendEntry`/`_persist`](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/session-manager.ts#L1016-L1049))

The default session file is under the agent sessions root, in a directory encoded from the cwd: `~/.pi/agent/sessions/<encoded-cwd>/<timestamp>_<sessionId>.jsonl`. `buildContextEntries()` keeps the latest compaction entry plus entries from `firstKeptEntryId` onward, and `buildSessionContext()` converts that into the messages sent to the model. The full history remains in the file. ([default session directory](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/session-manager.ts#L461-L488), [session filename allocation](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/session-manager.ts#L949-L956), [context reconstruction](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/session-manager.ts#L413-L479); [Pi session docs](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/docs/sessions.md#L1-L16))

`SessionManager.inMemory()` creates a non-persistent session with `persist = false`; the CLI uses this branch for `--no-session` and similar non-session modes. In that mode the compaction result can affect the running context but has no durable JSONL entry. ([in-memory factory](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/session-manager.ts#L1568-L1572), [CLI no-session branch](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/main.ts#L355-L359))

### Pi classification

- **Global:** yes, persistent `~/.pi/agent/settings.json` (or the configured agent directory).
- **Project:** yes, persistent `<cwd>/.pi/settings.json`, subject to project trust; project fields override global fields.
- **Per agent/model role:** no built-in persisted compaction scope. `AgentSession` receives a manager object, but the `CompactionSettings` shape has no agent id and the file paths contain no agent id.
- **Per session:** no for settings; yes for generated compaction summaries/boundaries in the session JSONL. A runtime `applyOverrides()` can make one manager/session differ temporarily, but that difference is not written to the session file or settings file.

## OMP (Oh My Pi)

### Durable configuration paths and schema

OMP's first-party settings documentation lists these layers and paths:

- Global canonical YAML: `~/.omp/agent/config.yml`; an existing `config.yaml` is accepted and updated in place.
- Global legacy JSON: `~/.omp/agent/settings.json`; migrated once to YAML when neither main YAML file exists, then renamed to `settings.json.bak`.
- Project native config: `<cwd>/.omp/config.yml`, with legacy `<cwd>/.omp/settings.json` still read and the YAML merged on top.
- One-shot `--config <file>` overlays, loaded for that process and never persisted.
- Runtime overrides, kept in memory and never persisted.

The active agent directory can be relocated by `PI_CODING_AGENT_DIR`; the OMP docs state that this moves the global config, auth store, and everything else below that directory. Native project settings intentionally use the process working directory's `.omp/` and do not walk ancestor directories looking for a different native `.omp/`. ([OMP settings table and relocation](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/docs/settings.md#L13-L26), [OMP migration details](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/docs/settings.md#L777-L784))

The schema has a single top-level `compaction` group, not an agent- or session-keyed map. At this revision it includes `enabled`, `midTurnEnabled`, ordered `methodOrder`, `thresholdPercent`, `thresholdTokens`, `reserveTokens`, `keepRecentTokens`, `autoContinue`, remote/handoff options, idle-maintenance options, and pruning options. Defaults include `enabled: true`, `midTurnEnabled: true`, `thresholdPercent: -1`, `thresholdTokens: -1`, an **unset** `reserveTokens`, `keepRecentTokens: 20000`, `autoContinue: true`, and `asyncEnabled: true`; the default method order is imported from `DEFAULT_COMPACTION_METHOD_ORDER` and is `remote, snapcompact, handoff, shake, soft`. ([schema declarations](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/config/settings-schema.ts#L2492-L2621), [idle/pruning declarations](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/config/settings-schema.ts#L2623-L2690), [typed compaction group](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/config/settings-schema.ts#L6119-L6137), [method order](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/session/compaction-methods.ts#L1-L58))

The current schema intentionally leaves `reserveTokens` unset as the provenance signal for adaptive small-window reserve calculation; it is not materialized as `16384` just because that is the default effective reserve. ([schema comment and key](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/config/settings-schema.ts#L2608-L2617), [reserve resolution](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/agent/src/compaction/compaction.ts#L320-L386))

### Loading and precedence

The `Settings` constructor stores the normalized `cwd`, `agentDir`, and optional config overlay paths. It records the global main YAML path under the agent directory, reads `PI_CONFIG_FILES` and explicit `configFiles`, and marks the object persistent unless `inMemory` or `readOnly` was requested. ([`Settings` constructor](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/config/settings.ts#L435-L515))

`Settings.#load()` loads the global and project branches, then the config overlays, and rebuilds the effective view in the documented order. `#readExistingMainYaml()` checks `config.yml` then `config.yaml`; `#readProjectSettings()` loads project settings providers and the native `<cwd>/.omp/config.yml`; `#loadConfigOverlays()` deep-merges each explicit overlay in order. ([load orchestration](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/config/settings.ts#L1277-L1295), [global filename selection](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/config/settings.ts#L1500-L1518), [project settings loading](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/config/settings.ts#L1521-L1557), [overlay loading](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/config/settings.ts#L1559-L1574))

The effective precedence is explicitly documented as:

```text
built-in defaults  <-  global config  <-  project config  <-  CLI overlays  <-  runtime overrides
```

The docs also distinguish environment variables from that single merge chain: feature-owned environment values are read by their feature, are not written back to YAML, and can override the persisted value. `PI_CONFIG_FILES` contributes overlay files before explicit `--config` files. ([precedence](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/docs/settings.md#L91-L126))

`#rebuildMerged()` implements the same order: global, then project, then the config overlay, then `#overrides`. Objects deep-merge recursively; scalar values and arrays replace the lower layer. ([merged view](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/config/settings.ts#L2649-L2687))

### What persists when a setting is changed

`Settings.set()` changes the global layer, marks the setting modified, rebuilds the effective view, and queues a background save. The save path re-reads the current global YAML under a lock and atomically writes it, preserving unrelated external changes. ([`Settings.set`](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/config/settings.ts#L618-L654), [save queue and global write](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/config/settings.ts#L2362-L2427))

The dedicated runtime `override()` method updates the private `#overrides` layer and fires effective-setting signals without queuing a save. The source labels that layer “Runtime overrides (not persisted).” ([runtime layer field](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/config/settings.ts#L435-L460), [`override()`](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/config/settings.ts#L642-L654))

The compaction-specific setting API follows that split. `SessionMaintenance.setAutoCompactionEnabled()` calls `settings.set("compaction.enabled", enabled)` and, when enabling an empty method list, writes the default method order with another `set()`. Therefore this dedicated setting mutation is persistent global configuration, not a session-local toggle. ([OMP compaction setting mutation](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/session/session-maintenance.ts#L4092-L4105), [OMP documented write target](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/docs/settings.md#L87-L89))

Ordinary settings writes do not target arbitrary project keys. OMP documents one project write exception: when `modelRoleStorage: project`, model-selector role assignments update only `modelRoles` in `<cwd>/.omp/config.yml`; other project overrides must be edited by hand. Consequently, a user changing `compaction.enabled`, `compaction.methodOrder`, or a threshold through ordinary `/settings`/`omp config set` writes the global active config, while a repository-specific compaction policy is a hand-edited project file (or a non-persistent overlay). ([where writes go](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/docs/settings.md#L87-L89), [project-local config](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/docs/settings.md#L228-L256))

### Runtime compaction and session persistence

`SessionMaintenanceHost` receives a `Settings` object from its owning `AgentSession`; the maintenance loop calls `settings.getGroup("compaction")` for pre-prompt, mid-turn, post-turn, overflow, idle, and speculative checks. `runAutoCompaction()` then resolves the configured method order and effective strategy from that group. ([host contract](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/session/session-maintenance.ts#L247-L252), [mid-turn settings read](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/session/session-maintenance.ts#L1581-L1587), [post-turn threshold read](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/session/session-maintenance.ts#L1981-L2022), [method selection](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/session/session-maintenance.ts#L2871-L2928))

The engine's pure `shouldCompact()` function returns false when disabled or when the context window is invalid; otherwise it compares context tokens to `resolveThresholdTokens()`. A positive fixed token threshold wins over the percentage threshold; otherwise a positive percentage is used, and the reserve-based path is the fallback. These are runtime calculations from the effective settings and active model, not persistent session metadata. ([`shouldCompact`](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/agent/src/compaction/compaction.ts#L336-L340), [`resolveThresholdTokens`](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/agent/src/compaction/compaction.ts#L362-L386))

When maintenance succeeds, `#commitCompactionEntry()` calls `sessionManager.appendCompaction()` with the summary, first-kept entry, token counts, method, and optional provider-preservation data, then rebuilds the active display/model context. ([OMP compaction commit](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/session/session-maintenance.ts#L1460-L1505))

`CompactionEntry` is a session entry with the summary, boundary, token counts, method, optional `details`, and optional provider replay/preservation payload. `SessionManager.#recordEntry()` appends it to the in-memory entry tree and calls `#appendToSessionFile()`; the allocated file is `<sessionDir>/<timestamp>_<sessionId>.jsonl` when persistence is enabled. ([OMP entry fields](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/session/session-entries.ts#L67-L91), [append compaction](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/session/session-manager.ts#L2362-L2395), [record and append](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/session/session-manager.ts#L1169-L1194), [file allocation](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/session/session-manager.ts#L1138-L1148))

The default OMP session root is `~/.omp/agent/sessions/<encoded-cwd>/<timestamp>_<sessionId>.jsonl`. `getSessionsDir()` is XDG-aware on supported platforms and honors the active agent/profile root; `computeDefaultSessionDir()` encodes the canonical cwd into a per-cwd bucket. OMP's session documentation describes compaction as a first-class entry and says context rebuild uses the latest compaction plus the kept/post-compaction entries while retaining the full transcript on disk. ([session root helper](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/utils/src/dirs.ts#L871-L874), [cwd bucket](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/session/session-paths.ts#L62-L84), [session directory computation](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/session/session-paths.ts#L185-L196), [OMP session layout](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/docs/session.md#L19-L43), [context reconstruction/persistence](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/docs/session.md#L413-L449))

OMP also exposes `SessionManager.inMemory()`, which constructs a manager with `persist = false` and `MemorySessionStorage`. A compaction performed through that manager affects the active runtime but does not produce a durable JSONL session entry. ([in-memory session factory](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/session/session-manager.ts#L3035-L3042), [OMP storage documentation](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/docs/session.md#L437-L449))

### OMP classification

- **Global:** yes, persistent YAML under the active `~/.omp/agent` (or relocated/profile agent directory). `/settings`/`omp config set` ordinary changes target this layer.
- **Project:** yes, persistent native `.omp/config.yml` plus project provider settings; project values override global values. Native `.omp` lookup is cwd-scoped, not ancestor-walked.
- **Per agent/model role:** no persisted compaction-settings dimension. The active agent/profile directory can separate whole global configurations, but `compaction.*` itself is not keyed by named agent or model role.
- **Per session:** no for settings; yes for generated `CompactionEntry` state in the session JSONL. Runtime overrides may differ between `Settings` objects, but are explicitly non-persistent.

## Wincode comparison (current inspected revision)

### File configuration layers

Wincode's shared config store defines only `ConfigScope = "global" | "project"`. `createConfigStore()` defaults the global config root to `${XDG_CONFIG_HOME:-<home>/.config}/wincode` and separately considers `<home>/.wincode`; it does not expose a write method—only `getSnapshot(workspace)` and `refreshSnapshot(workspace)`. ([scope/API](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/shared/config/config-store.ts#L11-L42), [global root and cache](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/shared/config/config-store.ts#L411-L447))

`loadSnapshot()` reads the global config root first, then `<home>/.wincode`, then project roots and each root's `.wincode` directory. At each location `wincode.jsonc` wins over `wincode.json`; later sources are merged over earlier sources. Objects merge recursively; arrays and scalar values replace earlier values. The root layout creates one config store/context at module scope for the process and passes a fixed workspace into the app. ([source locations/order](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/shared/config/config-store.ts#L272-L297), [snapshot merge](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/shared/config/config-store.ts#L363-L408), [merge rule](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/shared/config/config-store.ts#L163-L181), [process wiring](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/app/layouts/root-layout.tsx#L28-L45))

For the normal root-layout workspace, the project sources are therefore:

```text
Global:  ${XDG_CONFIG_HOME:-~/.config}/wincode/wincode.json(c)
Global:  ~/.wincode/wincode.json(c)
Project: <workspace>/wincode.json(c)
Project: <workspace>/.wincode/wincode.json(c)
```

The project-root helper can return an ordered ancestor list when called with a nested workspace, so the source code is slightly more general than this four-location summary. ([`getProjectRoots`](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/shared/paths/project-roots.ts#L4-L18), [local config documentation](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/shared/config/README.md#L8-L19))

Snapshots are memoized by resolved workspace. The store has an explicit `refreshSnapshot()` operation, but ordinary `getSnapshot()` returns the cached promise/value for that workspace. This is a process/snapshot lifetime detail, not persistent per-session configuration. ([memoized store](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/shared/config/config-store.ts#L427-L447), [store behavior test](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/shared/config/config-store.test.ts#L219-L262))

### Compaction resolver and precedence

Wincode's compaction defaults are `auto: true`, `enabled: true`, `keepRecentTokens: 20000`, `midTurnEnabled: true`, `overflowRecovery: true`, and `reserveTokens: 16384`. `CompactionSettingSource` distinguishes `default`, `session`, and config provenance (`global` or `project` origin). ([defaults/types](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/modules/conversations/compaction/config.ts#L11-L70))

`resolveCompactionSettings()` starts from those defaults, reads the `compaction` record from the merged config snapshot (with a compatibility fallback to top-level keys when no nested `compaction` record exists), validates configured values, and then applies `sessionOverrides`. Config origins are recorded per setting; valid session overrides become source `{ kind: "session" }`. ([config record/source logic](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/modules/conversations/compaction/config.ts#L90-L118), [desired-value resolution](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/modules/conversations/compaction/config.ts#L163-L240))

The Wincode effective precedence is therefore:

```text
built-in defaults  <-  merged global/project config  <-  sessionOverrides
```

Model pricing/context data is then used at runtime to derive the active context limit, reserve clamp, recent-token clamp, and threshold. Those derived values are runtime calculations, not persisted setting values. ([runtime derivation](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/modules/conversations/compaction/config.ts#L243-L321))

### Current UI override lifetime

`ChatView` initializes `compactionOverrides` and its ref to `{}` for each mounted conversation view. The dialog's only setting item is `auto`; `updateCompactionOverride()` updates the view state/ref and calls `useChat`'s setter, while `resetCompactionOverrides()` clears those values. The hook setter itself only copies the object into `compactionOverridesRef`; it does not call `ConversationStore`, `ConfigStore`, or a file writer. ([dialog item and handlers](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/modules/conversations/compaction/compaction-settings-dialog.tsx#L10-L49), [view state and hook wiring](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/modules/conversations/ui/views/chat-view.tsx#L94-L118), [update/reset](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/modules/conversations/ui/views/chat-view.tsx#L276-L290), [hook setter](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/modules/conversations/hooks/use-chat.ts#L617-L623))

Every compaction request resolves settings from the cached workspace snapshot plus the current override ref. Automatic maintenance also re-resolves the same combination. This makes the UI override live for the current mounted `ChatView`/`useChat` instance, but not durable across remount, process restart, or reopening the same conversation id. ([settings getter](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/modules/conversations/hooks/use-chat.ts#L530-L543), [manual/automatic use](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/modules/conversations/hooks/use-chat.ts#L545-L596), [automatic maintenance](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/modules/conversations/hooks/use-chat.ts#L640-L675))

At this revision, the visible dialog exposes only `auto`, even though the resolver and `CompactionSettings` type support reserve, recent-token, mid-turn, overflow-recovery, and enabled fields. That is a UI-surface fact; file configuration can still provide the broader values. ([dialog's single `SETTING_ITEMS` entry](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/modules/conversations/compaction/compaction-settings-dialog.tsx#L10-L24), [resolver settings type](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/modules/conversations/compaction/config.ts#L20-L28))

### Durable compaction state and exact local paths

Wincode's compaction module constructs an `AppendConversationCompactionInput` containing `sessionId`, `firstKeptUiMessageId`, `throughMessageUiId`, token counts, summary, trigger, model/variant, and optional prior-compaction id, then calls `store.appendCompaction()`. The resulting active messages are a synthetic summary message plus the kept tail. ([entry input](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/modules/conversations/compaction/compaction.ts#L451-L491), [persist and active context](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/modules/conversations/compaction/compaction.ts#L523-L598))

The SQLite schema makes this state session-scoped: `conversation_compaction.sessionId` is a foreign key to `conversation_session.id`, and `(sessionId, sequence)` is unique/indexed. The store verifies both the supplied session id and its workspace id before inserting; `getCompactions(sessionId)` filters by that session and workspace. There is no compaction-settings column in either table. ([session/workspace schema](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/modules/conversations/storage/schema.ts#L18-L48), [compaction schema](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/modules/conversations/storage/schema.ts#L89-L132), [append session/workspace check](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/modules/conversations/storage/drizzle-conversation-store.ts#L432-L484), [session-filtered reads](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/modules/conversations/storage/drizzle-conversation-store.ts#L544-L564))

The local database path is `WINCODE_LOCAL_DB_PATH` when set, otherwise `<resolveUserDataDir()>/conversations.db`. On macOS `resolveUserDataDir()` is `~/Library/Application Support/wincode`; on Linux it is `${XDG_DATA_HOME:-~/.local/share}/wincode`; Windows uses `%APPDATA%/wincode` (or the home fallback). ([database path](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/modules/conversations/storage/path.ts#L5-L12), [platform user-data path](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/shared/paths/user-data-dir.ts#L4-L21))

When a session route opens a conversation, it loads messages, the session row, and all compaction rows by the conversation id; it selects the latest compaction to rebuild active messages, but it does not load any saved compaction settings. ([session route loading](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/app/routes/sessions/$id/route.tsx#L61-L92), [active-message reconstruction](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/modules/conversations/compaction/compaction.ts#L101-L122))

### Wincode classification

- **Global:** yes for file configuration, from the two global roots and their `wincode.json(c)` files; no application writer exists in `ConfigStore`.
- **Project:** yes for file configuration; later project sources override global values according to the config store merge order.
- **Per agent/model role:** no compaction-settings dimension in the resolver or storage schema.
- **Per session:** the generated summary/boundary is durable per conversation session, but the UI-selected setting is only in the mounted session view and is not stored with that session.

## Comparison and implications

| Behavior | Pi | OMP | Wincode now |
|---|---|---|---|
| Persistent switch for automatic compaction | `setCompactionEnabled()` writes global settings; project file can mask it. | `Settings.set()`/`setAutoCompactionEnabled()` writes global YAML; project compaction must be edited directly. | `/compaction` toggle updates only a session/view ref; file config must be edited outside the UI. |
| Persistent threshold/budget | Global/project JSON fields (`reserveTokens`, `keepRecentTokens`). | Global/project YAML fields (`thresholdPercent`, `thresholdTokens`, reserve/recent budgets, method order, etc.). | Global/project JSON(C) fields; resolver also accepts ephemeral session overrides. |
| Does a resumed session carry its old compaction setting? | No setting snapshot; it carries compaction entries and uses current effective settings. | No setting snapshot; it carries compaction entries and uses current effective settings. | No; it carries SQLite compaction rows, while current UI overrides disappear on remount. |
| Where generated summary/boundary lives | Session JSONL under agent sessions root. | Session JSONL under agent sessions root. | `conversation_compaction` rows in local `conversations.db`. |
| Non-persistent mode | `SessionManager.inMemory()`/`--no-session`. | `SessionManager.inMemory()`. | No compaction-row persistence if the application uses a different store; the inspected default store is local SQLite. |

The central scope distinction is thus **configuration scope versus compaction-state scope**: Pi and OMP persist the former globally/project-wise and the latter per session; current Wincode persists the latter per session but exposes its interactive setting override only for the current mounted session view. A future Wincode persistence change should not put generated summaries into the global/project config or assume a session's compaction entry is a setting snapshot; those are separate contracts in all three designs. ([Pi separation](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/docs/compaction.md#L20-L57), [OMP separation](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/docs/compaction.md#L1-L24), [Wincode local separation](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/modules/conversations/README.md#L27-L32))

## Uncertainties and limits

- This report pins Pi and OMP source revisions above. OMP is an actively changing fork; current `main` or an installed build may have different schema keys or paths.
- Pi's `AgentSessionConfig` and OMP's `AgentSessionConfig` accept settings objects, so an SDK embedding can construct separate in-memory managers/objects. The source evidence establishes the built-in file scopes and the absence of a persisted agent-id/session-id compaction-settings key; it does not prohibit an embedding from inventing its own storage wrapper. ([Pi config object](https://github.com/earendil-works/pi/blob/853a80d26c90a14c1886f0ebb8ffaae133ca2185/packages/coding-agent/src/core/agent-session.ts#L201-L205), [OMP config object](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/session/agent-session-types.ts#L98-L117))
- OMP supports non-file `IndexedSessionStorage`/other storage abstractions and explicit session directories. The path conclusions above describe the default local file-backed CLI, not every host adapter. ([OMP session storage abstractions](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/docs/session.md#L478-L488), [session manager storage constructor](https://github.com/can1357/oh-my-pi/blob/969062200754ea02cfac922e5ebb8c608c079e15/packages/coding-agent/src/session/session-manager.ts#L558-L566))
- Wincode's config store has a `refreshSnapshot()` API, so a host can deliberately refresh a changed file. The current root composition creates the store once and the inspected compaction path calls `getSnapshot()`, so the stated process-cached behavior is the default path, not a claim that refresh is impossible. ([refresh API](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/shared/config/config-store.ts#L34-L37), [root composition](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/app/layouts/root-layout.tsx#L28-L45), [compaction snapshot read](https://github.com/sonwjnn/wincode/blob/3b8b39d62d1c160bf6495be8b38150c9ca314337/apps/cli/src/modules/conversations/hooks/use-chat.ts#L530-L543))
- No runtime experiment or broad validation was run; this is a source-and-first-party-document trace as requested.
