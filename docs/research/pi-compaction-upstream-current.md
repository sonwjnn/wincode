# Research: Upstream Pi compaction and auto-compaction

## Summary
Pi’s compactor is more than a pre-prompt token threshold: it can compact at the boundary between tool batches and has a single post-run compact-and-retry path for provider context overflow or a recoverable final `stopReason: "length"`. It uses a canonical session projection, boundary-aware usage estimation, iterative structured summaries, split-turn handling, persistent omissions for failed attempts, and extension/UI events. The inspected implementation is present in both current `main` (`3141dfdcf409e0bb2685a98ed298fa65920b1c7d`) and the latest published release checked, `v1.4.0` (`4a080252f06caf63a525d7873c5d94d3c23887e0`): the relevant `compaction.ts`, `agent-session.ts`, and compaction-doc blobs match at those refs. This does not identify the version installed on any particular machine.

## Findings

1. **Trigger timing and settings.** **Claim:** Automatic compaction triggers when context tokens exceed `contextWindow - reserveTokens` (defaults: reserve 16,384; keep recent 20,000). The session checks projected context after a tool batch and before the next assistant response via `prepareNextTurnWithContext`; it also checks before a new user prompt and after a run. It skips the between-turn check when the tool batch ends the run and there is no queued message to process. `enabled` is global; reserve/keep values support exact `provider/modelId` overrides, with independent fallback to ordinary values. **Sources:** [Compaction reference](https://github.com/earendil-works/pi/blob/3141dfdcf409e0bb2685a98ed298fa65920b1c7d/packages/coding-agent/docs/compaction.md#L27-L50); [session inter-turn projection](https://github.com/earendil-works/pi/blob/3141dfdcf409e0bb2685a98ed298fa65920b1c7d/packages/coding-agent/src/core/agent-session.ts#L750-L925); [settings](https://github.com/earendil-works/pi/blob/3141dfdcf409e0bb2685a98ed298fa65920b1c7d/packages/coding-agent/docs/settings.md#L64-L95), [schema](https://github.com/earendil-works/pi/blob/3141dfdcf409e0bb2685a98ed298fa65920b1c7d/packages/coding-agent/src/core/settings-schema.ts#L10-L28). **Support:** direct evidence. **Confidence:** high.

2. **Overflow and length recovery; persistence is not fully atomic.** **Claim:** A provider overflow or recoverable final length stop may cause one overflow compaction and fresh retry. A completed response that merely exceeds the context window is compacted without retry. Recovery persistently omits the failed assistant attempt and its matching tool results before compaction, then reuses that response as the failed-response input on retry. If compaction fails or is canceled, no compaction entry or internal retry is committed, but the omission edits remain. Length responses with tool calls follow normal tool/queue scheduling rather than ending immediately. **Sources:** [recovery checks and one-attempt guard](https://github.com/earendil-works/pi/blob/3141dfdcf409e0bb2685a98ed298fa65920b1c7d/packages/coding-agent/src/core/agent-session.ts#L2995-L3150); [paired recovery omissions](https://github.com/earendil-works/pi/blob/3141dfdcf409e0bb2685a98ed298fa65920b1c7d/packages/coding-agent/src/core/agent-session.ts#L1215-L1265); [auto-compaction commit/cancel path](https://github.com/earendil-works/pi/blob/3141dfdcf409e0bb2685a98ed298fa65920b1c7d/packages/coding-agent/src/core/agent-session.ts#L3140-L3330); [documented recovery ordering](https://github.com/earendil-works/pi/blob/3141dfdcf409e0bb2685a98ed298fa65920b1c7d/packages/coding-agent/docs/compaction.md#L94-L125). **Support:** direct evidence. **Confidence:** high. **Residual risk:** cancellation/failure leaves the transcript’s context-edit omissions in place without the recovery summary; this is an intentional partial state, not an all-or-nothing transaction.

3. **Usage estimates: boundary-aware in the projection path, not in the raw helper.** **Claim:** `estimateContextTokens(messages)` finds the most recent valid nonzero assistant usage and adds heuristic estimates for trailing messages; on its own, it has no compaction-boundary information. `estimateProjectedContextTokens(projection, branchEntries)` maps that usage back to its source entry and distrusts it if a later `context_edit` or `compaction` invalidates it, falling back to estimates over the current projected messages. AgentSession’s threshold paths use the projected estimator and also skip assistant events timestamped at/before the latest compaction boundary. **Sources:** [raw and projected estimators](https://github.com/earendil-works/pi/blob/3141dfdcf409e0bb2685a98ed298fa65920b1c7d/packages/coding-agent/src/core/compaction/compaction.ts#L120-L246); [threshold path and timestamp guard](https://github.com/earendil-works/pi/blob/3141dfdcf409e0bb2685a98ed298fa65920b1c7d/packages/coding-agent/src/core/agent-session.ts#L2995-L3150). **Support:** direct evidence. **Confidence:** high for these call paths; the raw helper must not be treated as boundary-aware by itself. **Uncertainty:** the parent reports a local stale-usage repro (`estimate32` followed by a threshold estimate of `90100`, with `needsAgain` remaining true after rebuild); I did not independently reproduce it or reconcile it with the projected estimator described above. Treat complete invalidation as unverified beyond the inspected internal paths.

4. **Summary preparation, split turns, serialization, and file tracking.** **Claim:** Pi walks backward over projected entries toward `keepRecentTokens`, never cuts at a tool result, and preserves tool-call/result pairing. If one user-message span alone exceeds the budget, it splits at an assistant message and generates a history summary plus a turn-prefix summary. Repeated compaction starts from the prior kept boundary and carries the previous summary forward. File-operation lists accumulate from Pi-generated compactions and summarized tool calls; custom extension summaries manage their own details. Before summarization, thinking is omitted and each tool result is truncated to 2,000 characters. **Sources:** [cut-point and preparation logic](https://github.com/earendil-works/pi/blob/3141dfdcf409e0bb2685a98ed298fa65920b1c7d/packages/coding-agent/src/core/compaction/compaction.ts#L300-L490), [prepare and compact/split-turn logic](https://github.com/earendil-works/pi/blob/3141dfdcf409e0bb2685a98ed298fa65920b1c7d/packages/coding-agent/src/core/compaction/compaction.ts#L775-L1120), [serialization and file operations](https://github.com/earendil-works/pi/blob/3141dfdcf409e0bb2685a98ed298fa65920b1c7d/packages/coding-agent/src/core/compaction/utils.ts#L1-L130), [repeated compaction and split-turn docs](https://github.com/earendil-works/pi/blob/3141dfdcf409e0bb2685a98ed298fa65920b1c7d/packages/coding-agent/docs/compaction.md#L50-L180). **Support:** direct evidence. **Confidence:** high. **Input-fit caveat:** docs say summary output is reduced as needed so input and output fit the context window, but the inspected compaction call path serializes the selected input into a single prompt and shows no general token-fit/chunking loop; only tool-result truncation is explicit there. The fit claim may be implemented in lower provider/AI layers; that was not established here.

5. **Hooks and user-facing behavior.** **Claim:** `session_before_compact` can cancel or supply a summary; its preparation exposes the selected messages, prior summary, file operations, effective settings, and retry intent. Success/failure events distinguish `manual`, `threshold`, and `overflow`. The interactive TUI shows compaction status, allows Escape cancellation, rebuilds the chat from compacted session context, displays the summary/cost when configured, and flushes messages queued during compaction according to whether a retry is pending. **Sources:** [extension hook contract](https://github.com/earendil-works/pi/blob/3141dfdcf409e0bb2685a98ed298fa65920b1c7d/packages/coding-agent/docs/compaction.md#L300-L375), [event types](https://github.com/earendil-works/pi/blob/3141dfdcf409e0bb2685a98ed298fa65920b1c7d/packages/coding-agent/src/core/extensions/types.ts#L775-L850), [interactive event handling](https://github.com/earendil-works/pi/blob/3141dfdcf409e0bb2685a98ed298fa65920b1c7d/packages/coding-agent/src/modes/interactive/interactive-mode.ts#L3620-L3700), [interactive regression tests](https://github.com/earendil-works/pi/blob/3141dfdcf409e0bb2685a98ed298fa65920b1c7d/packages/coding-agent/test/interactive-mode-compaction.test.ts#L1-L100). **Support:** direct evidence. **Confidence:** high.

6. **Brief Wincode comparison (parent’s local audit, not independently re-run here).** The parent found Wincode checks compaction before submission or after a whole multi-step `AgentTurn`, not between tool batches, and does not offer overflow recovery after a completed tool artifact. Pi’s `prepareNextTurn` threshold check and post-run overflow/length path are the biggest upstream behaviors to compare. The reported stale-usage repro is noted above rather than assumed resolved.

## Contradictions

- The documentation describes reducing the summary output limit to fit input plus output, but the inspected `compaction.ts` path does not reveal a general input token-fit or chunking mechanism. Lower-level provider behavior remains a possible explanation; unresolved.
- No contradiction between the raw usage helper and the projected threshold path: only the latter has branch-boundary invalidation. Calling the raw helper alone can mislead.
